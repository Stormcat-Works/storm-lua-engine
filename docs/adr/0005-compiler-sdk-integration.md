# ADR 0005: 言語処理SDKへの統合と公式フロントエンド

日付: 2026-09-26。

決定時の状態: 言語処理機能の統合方針を採用。実装は未着手。公式CLI/Webの同居は追加提案として推奨し、製品名・URL・既存配布の扱いは保留する。

現在の実装状況は[STATUS](../../STATUS.md)、公式フロントエンドの後続判断は[ADR 0006](0006-playground-coexistence.md)を参照する。以下は決定時の判断と未実施事項を保持する。

## 背景

実行エンジンとLua最適化ツールは別の責務を持つが、API仕様、診断、生成Luaの検証を同じ変更単位で整える価値がある。共通機能をSDKへ移しても、実行と最適化を常に同時利用する必要はない。

Storm Minの共通言語処理を移した後、専用ツールが薄いフロントエンドになることは許容する。コード量や旧リポジトリの役割維持を目的に、共通機能を重複所有しない。

## 決定

Engine側を解析・lint・リンク・minifyの実装正本にする。Rust/TSの利用者は専用アプリを経由せず直接利用できる。公開可能な実装とテストを選別し、追加の非公開コーパスを通常buildの前提にしない。

移行先は責務に沿ったEngine固有の新規クレートとする。`stormmin-*`の持ち込みや、巨大な`core`への一括改名は採用しない。具体的な所有範囲と依存方向は[統合設計](../design/compiler-sdk.md)で管理する。

実行系とコンパイラ系は独立した通常依存・初期化単位とし、`load()`に暗黙のminifyを追加しない。最適化は当面Vehicleのみとし、将来のAddon対応を現在の実行対応から自動推定しない。

欠陥・意味保存条件不足によるデフォルト無効パスは、削除または根本修正を統合完了条件にする。無効のまま移植、単純な全ON、永久opt-inへの移動は採用しない。exact等の意味論に基づく不適用は区別する。

## 公式フロントエンドの追加提案

同じリポジトリにSDKを使う公式CLIとWebを置き、Webの静的成果物をmakkii.jpへ配備する案を推奨する。SDKはアプリへ依存せず、公式アプリも公開APIの利用者として動かす。

初期用途は解析・ビルド・短縮・結果の入出力とし、完全なIDEやワールドシミュレータをもう一つ実装することは求めない。既存Storm Minの名前・配布をどう扱うかは、フロントエンドを二重実装しない条件の下で別途決める。

## 採用しない案

- 別リポジトリを維持するために言語処理の仕様と実装を重複させる。
- 実行VMを最適化器のParserへ置換する、またはコンパイラをVMの必須依存にする。
- CLI/WebのUI、FS、設定保存をライブラリの共通coreへ持ち込む。
- 公開履歴や第三者fixtureを未点検で取り込み、公開テストをすべて非公開データに依存させる。
- 独立した言語・評価順序テストを統合の名目で削除する。

## 帰結と未実施事項

API・実行系・言語処理・検証を同じ変更単位で整合させられる。一方、公開APIの絞り込み、fixture/buildの切り離し、配布物・feature/profileの分離、既定無効パスの解消には実作業が必要となる。

決定時点ではv0.1.0の公開APIを変更していない。新API、クレート、フロントエンド、パス修正、サイト配備が完了したことをこのADRの採用で代用しない。実装段階と検証ゲートは[統合設計](../design/compiler-sdk.md#11-実装順序と完了条件)を参照する。
