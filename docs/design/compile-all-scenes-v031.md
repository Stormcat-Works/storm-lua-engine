# v0.3.1 コンパイル全経路の時間削減

2026-10-04。API別名試行のMap追加時間削減に続き、**Mapあり・なしの絶対時間を共に短縮し、その上で同じ新実装のMapあり/なしを1.2倍以内、可能なら1.1倍以内に近づける**。`feat/minify-performance-v0.3.1`を維持し、独立に検証した変更ごとにcommitする。push・tag・release・本番配備は行わない。

## 固定条件

- 倍率の分母は同じ変更後のMapなし。分母を遅くしたり、追加作業をAPI完了後や計測外へ逃がしたりしない。
- 生成Lua、候補順・同点判定・target結果、診断、原文と生成物の指紋規則、標準Source Map v3とx_storm schema1、精度・理由・関連元・inline文脈・除去情報を維持する。
- 未知の由来を親・近傍で埋めず、検証を省略して速度を作らない。既知のエラー・trapも別に記録する。
- 原文返却、字句短縮、小入力を都合よく母集団から除外しない。平均比、各入力の中央値比、P90、最大、絶対追加msを分ける。
- 有限の実測で任意の入力・全CPUに対する厳密な時間上限を証明したとは扱わない。1.2倍を超える測定条件は未達として残す。

## 改善先

1. **全探索の共通解析。** single-use-global-forwarding / equal-scratch-value-coalescingで、未変更のASTに対してblockごとに再作成しているresolution/effect情報を、同じ構文が有効な期間だけ共有する。実変換後には必ず更新し、後のblockが古い解析を使わないようにする。通常経路の時間も短縮する。
2. **Map出力の固定費・字句経路。** 標準mapをJSON化して再度parseする処理、同じsnapshot/座標の再構築、不要な順序木や文字列複製を測る。小さいidentityと大きなlexical-mapの両方を対象にする。既存のcanonical bytesとhashの計算規則を変えない。
3. **共有前処理と結果整形。** 同じ原文の解析・字句解析・token baseline・診断等の重複を調べ、同一呼出内で安全に共有できる仕事だけを減らす。永続キャッシュ、版混在、入力依存の隠れた状態は追加しない。

## 比較対象

直前の検証済みAPI別名改善（実装`153a8c9`、記録`84e6353`）を基準に、その同一WASMを固定する。過去の基盤改善を今回の短縮率へ重ねない。

- 実Lua4,155原文の全探索／8192目標、Map OFF/ON。失敗は成功分布へ混ぜない。
- 固定30入力×8設定=240構成、未達target、safe/smallest・exact/tolerant・改行・property・host bindings。
- 小入力・空・コメント・Unicode/CRLF・最初からtarget以内・_ENV/extendedの字句短縮を明示的に含める。
- 既存の約2万文字制御と約13万文字描画の大きいfixture。
- analyze、通常/LifeBoatのリンクのみ・minify付き、compiler Workerの境界。

主観測は実SDKと同じWASMの完了時間。初期化・I/O・独立したvalidate呼出は別に記録し、Map生成そのものはcompileに含める。同じプロセス・事前実行・実行順の回転を用い、共有VM負荷とばらつきを記録する。単発全件走査と、複数回の代表/外れ値走査を分離する。

## 回帰と終了判断

旧方式の独立参照で各変更のコード・完全AST由来・選択順を比較する。最終候補では全コーパスの新旧完全map（producer/integrityだけ除外）・診断・検索統計、Native/WASM/SDK、3ブラウザー、独立package consumerを再検証する。

Mapなしの時間が増えた経路は、原因と測定ばらつきを区別し、実装による回帰なら修正か不採用にする。全体平均が1.2倍以下でも最大目標の達成とはしない。次の実装候補は実測に基づいて選び、性能のために意味論・マップ情報を削らない。
