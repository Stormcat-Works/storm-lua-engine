# v0.3.1 全経路高速化の継続 — 2026-10-05

目標は[全経路計画](compile-all-scenes-v031.md)のまま、Mapなし/あり両方の絶対時間を短縮し、同じ新実装同士でMap比1.2以下、可能なら1.1以下を目指す。平均比で個別条件を置き換えず、Mapなしを遅くする方法は採らない。

今回の比較元は、直前の完了済み実装`a400c55`。未保存だった前回の[実測記録](../verification/compile-next-round-20261004.md)を先に確定し、比較用WASMのSHA-256も照合した。前回の改善は今回の効果へ再加算しない。

## 優先して調べる箇所

1. 効果解析で何度も行う組込みAPI参照の文字列組立て。問い合わせが分類だけを必要とする場合、同じ意味を持つ借用表現で処理し、未観測の文字列を確保しない。
2. ASTの走査・サイズ判定・書換えで使い捨てる葉ノードの複製と、同一入力への重複処理。公開callbackの順序・親slotの観測/変更・NodeIdの契約を守る。
3. 生成順に並んだ位置のUTF-16変換、および同じ識別子が繰り返される字句由来の確保。一般のsource map validatorや外部入力の検査を省略しない。
4. コーパスと大きな描画で残る追加費用は、計測してから追う。以前撤回したscalar hash索引・一括JSONブリッジを無条件に再導入しない。

変更は独立した旧方式との一致・Native検査を通してから同じWASM入力で比較し、改善が確認できた単位をcommitする。採用しなかった試行も記録する。入力を跨ぐ永続cache、探索の打切り、source mapの精度/理由/件数の削減、非互換schema変更は対象外。

## 受入確認

固定240設定、目標未達、新旧マップの相互検証とWorker混成、44シーン、通常/LifeBoat/複数module build、実コーパス4,155原文を使用する。構文/環境エラーと既知trapは成功測定と分ける。全体コーパスは広い1回観測、シーンと重点入力は反復で補い、同じMapなしを分母にする。Mapは完成したJSONが返るまで時間に含める。

Native、WASM、SDK、3ブラウザーの既存Playground flow、梱包済みパッケージも確認する。本ブランチへのローカルcommitだけを行い、push・公開・main/releaseの更新は行わない。
