# v0.3.1 借用印字とリテラル処理の性能改善

2026-10-05。全経路の性能条件は[全経路計画](compile-all-scenes-v031.md)を維持する。Mapなし/ありの絶対時間をともに短縮し、比率は同じ新実装で1.2以下、可能なら1.1以下を目指す。出力を遅延させたり、通常処理を遅くしたりして比率を作らない。

基準は`627f8d1`の完成済みcompiler。API別名候補、小整数出力、関係のprefix照合は既に適用済みの改善で、今回の効果へ再加算しない。[基準の検証](../verification/compile-latency-20261005.md)を先に保存した。

## 今回の候補

1. Printerの識別子・演算子・変更しない数値/文字列を、immutableな入力ASTから借用する。公開結果は今までどおり所有Stringと完全なemission一覧で返す。親への連結・区切り・位置補正の順序は維持する。
2. 固定個数の演算子組み立てと、連続した引数の印字で、使い捨てのFragment配列を作らない。改行のカウント順を変えるblock/elseifの並べ替えは行わない。
3. 小さな十進整数の読み取りと、整数リテラルの二重検査を削減できるか測る。浮動小数/整数の区別、64-bit境界、負のゼロ、非有限値、不正入力の扱いは独立参照と一致させる。

変更はWASMの試行で効果を確認してから採用する。Mapだけを意識して通常経路を悪化させない。ソースマップJSON側の試行で以前改善しなかったものは繰り返さない。これらの候補が不採用なら、patchと試行結果をローカル検証領域へ残し、製品コードは元に戻す。

## 検証と測定

公開API・schema1・生成Lua・検索順/同点処理・全由来データを維持する。Rustの回帰、同じ入力のWASM新旧比較、固定240構成、通常/LifeBoat/Worker、実コーパスの成功/既知失敗を確認する。全コーパスの各1回観測と、44シーン/抽出コーパスの反復値を別扱いにする。Mapの完全生成を呼出の内側へ含め、外部validatorやI/Oは別に測る。

基準・候補WASMのhash、producer、warmup・繰り返し回数・順序・負の観測を保存する。変更は`feat/minify-performance-v0.3.1`へ意味のある単位でcommitする。push・公開・main/release変更は行わない。
