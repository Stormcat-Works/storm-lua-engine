# v0.3.1 Source Map追加時間の削減

2026-10-04。実コーパスの結果を基に、**同じ開発版・入力・設定でMapあり/なしの所要時間差を減らす**。全体短縮時間の改善とは区別し、Mapなしを遅くして倍率を下げない。既存の`feat/minify-performance-v0.3.1`を使用し、検証した単位でcommitする。push・release・本番更新はこの作業に含めない。

## 根拠と優先順位

[実Luaプロファイル](../verification/corpus-pass-profile-20261003.md)では、API別名選択と名前短縮がMapで増えた時間の約70.3%を占めた。1.2倍目標は維持する。単一の巨大描画例だけでなく、実Luaの分布と原文返却の固定費も別に確認する。

今回の最初の対象は`api_aliases::optimize_api_aliases`。現状は、別名集合を試すたびに元の由来を保持したASTを生成し、scope renameを適用してサイズを比較する。不採用候補にも同じデバッグ情報を生成している。

## 第一段階

- 別名の走査、初期候補、除去/追加の順、4-round探索、最大8追加候補、同点判定と最終空集合比較を維持する。
- サイズ比較用の入力では由来だけを外し、NodeId・SymbolId・Lua構造と同じ解析を使用する。
- Mapありでは、採用した別名集合だけを元の完全な由来付き入力へ再適用する。最後のscope renameも由来付きで行う。
- Mapなしの経路は不要な再適用をしない。
- 再適用前に使った元の由来・型付き関連元・inline文脈・除去記録を候補の不完全な情報で置き換えない。

この段階では、名前割当のアルゴリズムや探索の剪定を変更しない。追加の改善を行う場合も測定とcommitを分け、主指標がMap追加費用か通常経路の費用かを明記する。

## 検証

1. 既存の未コミット性能改善を、プロファイルに使用したsnapshotと照合してから基準commitにする。
2. API別名最適化の旧方式をtest-onlyの独立参照に保持し、選択した別名集合・saved・生成Lua・由来情報と構文を比較する。
3. 既に全67パスで変換された入力、通常/短縮済み入力、shadow/名前衝突/固定API/欠落由来/JSON復元等を含める。
4. 固定240設定と実コーパスで、Map有無と変更前後のコード・診断・候補統計を比較する。mapはproducer/integrityだけを除いて全体比較する。
5. 既存に存在するcompile errorやWASM trapを今回の成功件数へ含めない。変更で新たな失敗や失敗の隠蔽を生じさせない。
6. Native、WASM、SDK、Worker、ブラウザー、独立パッケージconsumerで回帰を確認する。

## 性能の判定

計測器を入れていない変更前/後のWASMを同じprocessで読み、事前実行と実行順の交互化を揃える。外部のマップ再検証、初期化、I/Oは別に測る。Mapありのcompileには完全なマップの生成を含める。

報告する指標は以下。

- 同じ新実装のMapあり時間/Mapなし時間。
- Mapあり−なしの差分の変更前後比較。
- MapなしとMapあり、それぞれの絶対時間の変化。
- 実コーパスの平均・中央値・P90と、1.2倍以下の割合。最大を都合よく除外しない。
- 小さい原文返却と、最適化探索を行う経路を分ける。

1.2倍に届かない構成は未達として残す。理由の省略、精度低下、map生成を計測外へ逃がす変更、時間制限による探索打切りは行わない。新機能・スキーマ非互換変更は含めない。
