# 最適化説明とSource Map拡張 — 採用決定

決定日: 2026-10-01。利用者が承認した方針。対象はv0.3.0開発ブランチで、既公開v0.2.1を差し替えない。

## 正本と配布形式

コンパイラ内部の構造化された由来情報を正本とする。通常の配布形式はSource Map v3（ECMA-426）の標準フィールドと`x_storm`拡張を一つのJSONに格納する。標準mappings/namesの意味を変更しない。独自拡張を理解しないconsumerでも標準の位置対応を読める。SARIF/LLVM Remarks/DWARFの実装は今回の必須条件ではない。

最適化説明はLLVM Remarksの「何をしたか・適用根拠・採用結果」を分離する考え方、複数の由来とインライン文脈はMLIRのFusedLoc/CallSiteLocの考え方を参考にする。LLVM/MLIRへの依存追加・移植は行わない。

## 版と成果物の同一性

標準`version`は3を維持する。`x_storm.schemaVersion`と`producer.name/version/revision`を別に保存する。エンジン版は必須。開発版のrevisionが分からない場合はunknownを明示し、実装していないバイナリ指紋を捏造しない。実効コンパイル設定、原文snapshotと生成LuaのSHA-256、座標単位を保存する。版だけでコード/マップの一致を判断しない。

形式の読取互換性はschemaVersion、生成実装はproducer、生成物の照合は内容hashが担当する。同長の別コード、別snapshot、誤った拡張スキーマを明示rejectする。

## 由来位置の改善

1. 同一出力のidentityと正確なtoken copyを、構文単位の帰属から区別する。保持された演算子・キーワードの位置を可能な範囲で精密化する。新しく生成した演算子を元の同じ文字へ無根拠に対応させない。
2. 関連元に役割を付ける（寄与元・定義・呼び出し・実引数・仮引数使用など）。細かな子の位置と、外側のインライン文脈を別に保持し、リテラルからも展開元を辿れるようにする。
3. 明示的な削除・置換・統合記録を持つ。逆引きで広い関数範囲に含まれるだけの削除行を実行可能と扱わない。記録されていない消失理由は推測しない。

## 最適化理由

各区間の変換識別子に加え、判断した時点の安定した理由コード・根拠データ・関連位置を保持する。長いUI文章や全候補のログを複製しない。「適用してよい根拠」「局所変化」「採用候補の選択理由」は区別する。局所的な短縮量を足して全体の寄与量としない。数値近似を完全同値と説明しない。

最終成果物には採用候補だけの説明を出す。不採用trialの変更・削除・理由を漏らさない。不可逆的な処理を表示時に元式の再評価で復元したことにしない。全探索の全履歴は通常のマップへ保存しない。

## 実装・検証順序

- 内部型と候補/Worker転送を拡張し、identity/copy、型付き関係・文脈、根拠・削除記録を実装する。
- Source Map v3と拡張のencoder/validatorをbuild層へ実装し、minify・通常build・LifeBoat build・WASM/TSを接続する。
- 元の実測例（`storm-lua-engine-provenance-examples-20261001.md`）の定数化、名前短縮、展開、共有、ループ、削除、identity、Unicode/CRLFを再実行する。
- 全67パス・代表240設定の同一出力とUnknown0、外部Source Map reader、誤った成果物拒否、Node/WASM/ブラウザーを検証する。
- 追跡/説明ON-OFFを同条件で測定する。大きな劣化はprofileして修正する。最適化を弱める、候補を減らす、時間制限を新設する方法で性能を装わない。

本書は確定した契約と作業順序であり、記載した全機能がすでに実装済みという意味ではない。完了状態はSTATUSとverificationへ記録する。

## 今回の境界

元変数の値・生存区間・実行中の保存先の復元、bytecode命令から生成式へのVM側対応、履歴トレース、特定の描画ループ反復の動的復元は後続。今回は静的な由来と最適化説明を改善し、位置マップを実行状態の完全復元と混同しない。Playgroundの完全な対話UIはP5として別途管理する。

参考: [ECMA-426](https://tc39.es/ecma426/)、[LLVM Optimization Remarks](https://llvm.org/docs/Remarks.html)、[MLIR locations](https://mlir.llvm.org/docs/Dialects/Builtin/)。
