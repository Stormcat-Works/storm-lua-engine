# Lua環境と最適化の契約

この仕様は環境プロファイル対応の開発ブランチを対象とします。公開済み0.1.0に遡って適用される仕様ではありません。

## 二つの独立した選択

`vehicle` / `addon`はI/O、コールバック、ホストサービスの実行モデルです。`environment: "game" | "extended"`はLuaに公開する機能集合です。数値モード、命令予算、ホストデバッガも、それぞれ独立した契約です。

既定は`game`です。`extended`は明示選択し、実ゲームでの動作互換を意味しません。定義の正本は`storm-lua-spec::environment`であり、runtime、解析、ビルド、minifyが共有します。生成済みの`ENVIRONMENT_CATALOG`も同じ定義を参照します。

| 項目 | game | extended |
| --- | --- | --- |
| `debug.log` | 使用可能。`debug`のメンバーは`log`だけ | 同じ。標準Luaのdebugライブラリは公開しない |
| `print`、`pcall`、`xpcall`、`error`、`assert`、グローバル`unpack` | 初期値は`nil` | 使用可能 |
| `io`、`os`、`package`、`load`、生のdebug API | 非公開 | 自動開放しない |
| ユーザー定義の同名ローカル・関数 | 通常のLuaとして利用可能 | 同じ |
| 任意のホスト値・関数の追加／置換 | 設定を拒否 | 明示したbindingsを初期化前に適用 |
| ホストのブレークポイント・ステップ・状態検査 | 使用可能 | 使用可能 |

ゲーム環境は確認済みのAPIを基礎とするSDKの提供契約です。表の全項目、すべてのゲーム版、VehicleとAddonの全差異を独立の実ゲーム試験で証明したものではありません。特に`assert`とグローバル`unpack`の扱いは保守的な提供範囲であり、Lua標準機能だから実ゲームに存在すると推定しません。乱数列、property精度などの未検証事項は既存仕様に従います。

## ログ、デバッガ、エラー

`onLog`はログ配送先だけを選びます。指定しても`print`は生えません。`debug.log`は両環境で利用でき、出所と元のバイト列を持つログを生成します。`enableLogs` / `devLogs`で`print`を要求する操作はextended専用です。

ホスト用デバッガはLuaの標準debugテーブルとは別です。`debug.getinfo`や`debug.sethook`をスクリプトへ渡さずに、ホストからスタックや変数を観測できます。watchは明示的な副作用を持ちます。任意の外部フックでSDKの命令制限フックを置き換えるAPIは提供しません。

ゲーム環境で`pcall`がnilであっても、ホストはSDKのエラー戻り値を処理できます。extendedの保護呼び出しも、命令予算の超過を捕捉し続けて無制限実行に変えることはできません。

## 外部名と動的な環境参照

ソース内で代入されないグローバルを、存在しないものとして`nil`へ変換したり別名へ改名したりしません。外部から供給される名前と、自分で定義した名前を区別します。グローバルnil伝播は、選択されたゲーム契約で不在と確認できる名前に限定します。

`_ENV[key]`は有効なLuaです。警告を出して意味の変わる最適化を継続することはしません。現在の実装は、`_ENV`への参照・別名化・再束縛があるチャンクを字句短縮へ切り替えます。extended、またはホストbindingsを指定した場合も同じ経路を使います。

字句短縮では、コメントと余分な区切りだけを減らします。識別子、数値・文字列リテラルの原綴り、トークンの順序、元の行番号を保持します。`pcall`が捕捉するエラー位置も、この行番号保持の対象です。property固定化、グローバル／ローカル改名、式移動、定数畳み込みなどのASTパスは適用しません。

結果には`conservative-minification`診断と`search.mode: "lexical"`を返します。短縮不能や目標文字数未達は、意味を変える探索へ戻る理由になりません。実際の出力文字数を報告し、未達でも有効な生成物を返します。

この経路は任意のLuaコードをゲーム対応へ変換するものではありません。たとえば実行時の動的キーがnilの関数を指すなら、原文も生成物も同じように失敗します。動的環境から実際にどの名前を参照するかを静的に証明したという扱いもしません。

## 解析と生成の診断

共有の環境検査が判定し、編集用`analyze`は互換性警告、単一ソース`minify`とプロジェクト`build`はエラーとして返します。目標サイズによる早期終了、並列候補の準備・評価・最終化でも、同じ条件を維持します。

`type(pcall)`、`pcall == nil`などの存在確認と、同名のユーザー定義ローカルは拒否しません。`_ENV`を再束縛できる入力では元のグローバル環境を仮定した可否判定を行わず、字句短縮の制約を通知します。未知の動的参照を成功保証として説明しません。

公開0.2.0/0.2.1のAddonコンパイラは未対応です。この開発ツリーでは[buildAddon](addon-build.md)として非短縮のinclude-onceリンク・構文/環境検証を追加しています。Addon最適化や全server APIの解析は未提供です。Addon実行やextendedを根拠にVehicle用のphase検査・8192文字目標・最適化を流用しません。

## ホストbindings

ホスト値と同期関数は`bindings.values`、`bindings.functions`へdot区切りのパスで指定します。値の`nil`指定は削除です。重複、親子パスの競合、不正な名前、設定済みserverとの衝突を拒否します。ホスト関数は明示的な戻り値リストを返し、関数・thread・userdataを所有値として転送しません。

設定はユーザーコードより前に適用し、Vehicle reset／Addon reloadで再適用します。ホストclosure自身の外部状態はホストが所有し、VMをresetしても暗黙に巻き戻しません。SDKの低レベル`configure`は信頼されたmlua密結合の拡張口であり、高レベルの互換性保証とは区別します。

コンパイラへも同じ`environment`と`hostBindings`を渡します。TypeScriptでは`bindingPaths(bindings)`で一覧を作れます。標準関数の置換を最適化器に知らせず、標準関数の定数畳み込みを適用してよいという契約にはしません。
