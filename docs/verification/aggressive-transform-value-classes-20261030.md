# constant-folding の積極的変換 3 件の値域ガード欠落（2026-10-30、未公開）

境界スイート v6（and/or・基本 fold 以外の積極的恒等式・変換を対象）
で、constant-folding の積極モードにある 3 件の変換が、被演算子の
値域（型・有限性・精度級）を確認せずに発火し、意味を変えている
ことを確認した。いずれも単独パス無効化で constant-folding の
無効化でのみ直る。

## 1. ビットテストの剰余形変換（modulo_bit_test）

`(x & mask) == 0`／`~= 0`（mask は 2 の冪）を `x % (2*mask)` との
比較へ書き換える変換は、`x` が整数表現を持つ場合にしか `&` と
一致しない。`x = 5.5`（小数）、`x = 1/0`（inf）、`x = 0/0`
（NaN）、`x = 1e19`（整数範囲外の整数値 float）では plain は
実行時エラーになるが、最適化後は剰余形がそのまま評価され、
エラーが消えていた。整数値の負数（-3）・6.0・2^53 境界は
両形が一致することを確認済み。

修正：発火条件に、被演算子が整数値であることの証明
（`provably_integer_valued`：整数リテラル、整数範囲内の整数値
float リテラル、ビット演算式）を追加した。名前や一般式では
発火しない。既存の provenance テスト 1 件は、名前での発火を
前提にしていたため、ビット演算式を被演算子とする形へ入力を
差し替えて変換の origin 検証という目的を保存した。

## 2. 因数分解形（x + (-x * t) → x * (1 - t)）

`local p = 1/0` に対し `p + -p * 2` は NaN だが、因数分解形
`p * (1 - 2) = -inf` になり、自己比較の結果が反転した。有限の
非リテラル x に対しても再結合による丸め変化の余地がある。

修正：第171ラウンドと同型に、発火条件へ「共有被演算子が有限の
数値リテラルであること」（`finite_number_literal`）を追加した。

## 3. 逆数乗算の除算化（divide_by_literal）

`x * (1 / d)` を `x / d` へ書き換える変換は、1/d が不正確な
d（3, 7 等）では丸めた逆数との乗算と除算が 1 ulp ずれ、
`x * (1/3) == x / 3` のような等価比較の結果が反転した。
これはリテラルの近似ではなく演算そのものの書き換えである。

修正：分母が 2 の冪（逆数が正確）の場合に限定した。兄弟の
逆数変換（x * 0.5 → x / 2 等）が従来から 2 の冪に限定して
いたのと同型の規律である。

## バグではないと切り分けたもの

`math.sqrt(5)` の畳み込み結果が `2.236067977` と短縮され
等価比較が反転する件は、tolerant モードのリテラル近似
（`aggressive_literal_node`、リテラル許容誤差の既定は
abs/rel とも 1e-6）の設計内挙動であり、相対誤差 2.2e-10 は
上限の内側である。exact モードでは発火しない。バグとして
扱わない。
