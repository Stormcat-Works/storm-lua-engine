# 純粋呼出キャリア合成にローカル予算チェックが無く、上限のチャンクが読込不能コードを生成した（2026-10-31、未公開）

## バグ

w6 第51サイクルのトグル狩り（境界スイート v16 全 102 件 × パス ID 73 件 = 7,446 回の単一パス無効化実行）で発見。同時有効ローカルがちょうど 200 のチャンク（ローカル 195 件＋作業ローカル＋数値 for の 4 枠、c51-suite-v16/v16-b8b-chunk-skip-200、および 199 の対照 v16-b8a-chunk-fire-199）について、`available-expression-reuse` を無効化すると opt / safe / target の全てが vm-error になった（plain と全有効時のベースラインは一致）。無効化時の生成コードでは、各宣言が「前の値の複写＋次の呼出結果」の二重ローカル連鎖形になり、チャンクのローカル数が上限を大きく超えていた。

## 原因箇所

`crates/storm-lua-minify/src/passes/available_expressions.rs` の `SynthTransformer::flush`（pure-call-carrier-synthesis）。同一の純粋呼出が直線区間に 2 回以上現れると、グループごとにキャリアローカルを 1 つ挿入するが、囲み関数の同時有効ローカル上限を確認していなかった。通常は再利用パス（available-expression-reuse）が出現箇所を先に主張するため合成は発火しにくいが、再利用をトグルで無効化すると全出現が合成対象になり、上限近傍の関数・チャンクで挿入が溢れる。第208ラウンド（S1／MR／SMC）・第212ラウンド（LICM）と同種の欠落の 5 例目。なお同じトグル狩りで、root-local-globalization 無効化時に api-alias ローカル化の別名ローカル挿入が上限を超える件（対象モードのみ）も見つかったが、そちらはレイアウト／勝者選択と絡むため本ラウンドでは扱わず、切り分け結果を作業記録に残して親へ報告した。

## 修正

`SynthTransformer` に、囲み関数ごとの予算管理を追加した。

- 関数本体への入口 2 箇所（collect_expr と recurse_functions の Function 腕）で `(本体, 引数数)` を fn_stack へ積み、チャンク直下の区間は暗黙の最外文脈（ルートブロック、引数 0）として扱う。
- 関数ごとに `max_active_locals`（共有ヘルパー、その時点の入力ツリーで算出）をメモ化し、本パスがその関数へ挿入したキャリア数を数える。キャリアを作る直前に `fn_max + inserted + 1 > MAX_LOCALS` ならそのグループをスキップする。会計方法は第208・212ラウンドと同じ保守的な関数全体最大値方式。
- 回帰テスト4件を追加: チャンクが上限ちょうどでスキップ／上限未満で発火（対照）／関数が上限ちょうどでスキップ／2 グループ目が 1 グループ目の挿入で埋まった予算に当たってスキップ（累積会計）。文字数ゲート（出現回数が少ないグループは予算以前に不発）で空転しないよう、各グループの出現回数は 8 に揃えた。

上限系の回帰テスト3件は修正前のコードで失敗し、発火対照1件は修正前後とも通過することを確認済み。

## 検証

- ワークスペーステスト全通過（1,530 件 = 第212ラウンド時点 1,526 + 新規 4）。fmt 通過、clippy は本変更への新規警告なし。
- 再現 v16-b8b / v16-b8a は `available-expression-reuse` 無効化時も全5構成で一致に転じた。base / head の diffexec は同条件で機能的に同定済み（base は opt / safe / target が vm-error、head は全構成 ok）。
- 境界ドライバ 242 件（sweep 968 行／diffexec 1,210 行）を修正後に再実行し、フラグ集合（既知 9 件）とトレースハッシュが第212ラウンド統合時点と完全一致。
- Tier FULL（base `e225ac969` = FULL-VERIFY-TIP → head、実世界コーパス 4,155 件 × 4 条件 = 16,620 行、開発ホスト1）: base / head の corpuscheck TSV がバイト単位で完全一致（SHA-256 `e88ee2b4…`、両側とも ok 4,128 / error 27 × 4 条件）。本修正は上限近傍でのキャリア合成抑制のみのため、無対象コーパスへの影響ゼロは設計どおり。回帰 0 件。
