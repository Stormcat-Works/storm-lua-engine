リリース前レビュー（run5）の16件は独立検証で全件 CONFIRMED となり、最終

16件全てを修正し、再検証した。コード先端 `1265a0b`（ベース `96d5691`）。

## 修正内容

通常経路:

- Q01（minify root_globals）: 関数内で書かれるルート束縛が、チャンクレベルで
  二項演算の直接の名前オペランドとして読まれる場合、その読み取りは兄弟側の
  呼び出しの後に評価される（実測）。書き込み呼び出しを含む兄弟部分木がある
  場合は大域化を除外した。
- Q02（single_use_forwarding）: 式が builtin 呼び出しを含み全域数値式でない
  場合、単回使用の前方送出を行わない（評価時点の移動による誤りを防止）。
- Q03（analysis effects）: テーブルコンストラクタのキーが静的に合法と証明
  できない場合、その文は送出しうると記録する（nil キーは必ず送出する）。
- Q04（global_stores の total_numeric_expression）: `math.max()` /
  `math.min()` の空引数は全域でない（PUC はエラー）。引数必須とした。
- Q05（available_expressions）: 関数サマリ経由でフィールドを読む候補は、
  フィールドへの書き込みがありうる文を跨いで再利用しない。
- Q06〜Q08（build linker）: レジストリを単一の lexical テーブル
  `__stormmin_link_modules` へ再設計した。初期化 glue は全 require 位置へ
  発行され（Q06）、キャッシュ判定は package.loaded と同じ truthiness で
  false 返すモジュールを再読込し nil は true へ正規化する（Q07）。生成参照は
  lexical に解決され、ローカル `_ENV` の覆いに影響されない（Q08）。エントリ
  チャンクのローカル数が上限近傍の場合はレジストリ宣言を大域名へ退避し、
  リンクでロード不能化しない。
- Q09（vm dialect）: 多重代入の代入先評価時点を実測し直した。同一関数
  ローカル（ベース・キー）と upvalue ベースは保存時点で遅延読み取りされ、
  それ以外は早期に確定する。R210 の last-wins 値意味論は不変（キー形の
  VM (nil,2) vs PUC (nil,1) は承認済み方言差異として維持）。従来テスト1件は
  凍結モデルの誤った期待値を持っていたため実測値へ是正した。
- Q10（vm dialect）: 一時テーブルが 200 ローカル上限を押し上げる文では
  書き換えを行わず、ロード可能な PUC 形のままにする。
- Q11（vm dialect）: トークンパーサに深さ上限（1000）を共有カウンタで
  導入し、深い入れ子は SIGABRT でなく PUC 相当の通常エラーを返す。

フォールバック経路（load_legality）:

- Q12: 関数入り口で active_locals を 0 に戻し、引数の二重計数を解消。
- Q13: for の隠れローカルを計数した（numeric 4、generic は名前数+3）。
- Q14/Q15: ラベル解決を自ブロック内へ限定し、repeat 本体末尾ラベルの例外を
  「goto がローカルを飛び越えない場合」に限定した。
- Q16: 構文パーサが `return` の後の2個目の `;` を拒否するようにした
  （両経路共通）。
