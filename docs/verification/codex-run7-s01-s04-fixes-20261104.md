## 修正内容

- S01（minify、root_globals、High）: 読み取り時点の保護を「全ての
  読み取り位置」へ一般化した。従来の除外は代入先の基底と二項被演算子
  のみで、インデックス基底 `t[f()]` やコンストラクタの計算キー
  `{[k]=f()}` の読みは、キー／値の呼出しが先に再束縛しても大域化
  され、再束縛後の値を読んでいた（Q01＝直接読み、R01＝括弧付き二項
  被演算子に続く3つ目の同族経路）。除外走査を単一の分類へ統合した:
  PUC が遅延評価する位置（二項被演算子、インデックス基底、コンスト
  ラクタの計算キー）は保護し、排出時に複写される位置（呼出しの関数
  と引数、return 値、コンストラクタの値、代入先キー、for の境界、
  メソッド基底、連結・比較の被演算子）は保護しない。分類は実測で
  確定し（25位置の対照バッテリー）、走査は括弧を剥がし入れ子を
  再帰するが関数境界は越えない（upvalue 読みは大域読みと同様に
  実体化されるため）。回帰テストは分類を列挙する（遅延位置は保持、
  複写位置は大域化が進むことの両側）。
- S04（minify、signed_factoring、High、Smallest 限定）: 因数分解した
  式がフィールドを読む場合の失効モデルを、available_expressions の
  Q05 修正と同水準にした。従来の分割判定は書込み先の BindingId と
  式の読み取り集合の直接比較のみで、別名経由の書込み（`local u = t`
  の後の `u.value = ...`）を取りこぼし、古い値を全出現へ使い回して
  いた。式が可変インデックス読みを含む場合、フィールドを書く可能性
  のある文（前出現文と間のバリア走査の両方）でグループを分割する。
  判定ヘルパーは available_expressions から共有する。本丸形状の
  回帰テストは修正を無効化すると失敗することまで確認した。
- S02（build、リンカ ambient 隔離、Medium）: ambient の `_ENV`
  隔離セルを、通常モジュール（define_module）と同じく本体関数の
  外（do ブロック側）へ移した。従来は IIFE 本体の内側に置かれ、
  ambient 本体フレームのローカル（上限200）／レジスタ（上限255）
  予算を +1 圧迫したため、ローカル200個や戻り値254個を使う
  ambient メンバーが元はロード可能でも生成物がロード不可になった。
  外へ置けばセルは upvalue として捕捉され、本体フレームの予算は
  元のチャンクと同一になる。回帰テストは両形状の生成形とロード
  可能性を固定する。
- S03＋潜在リスク（VM、dialect、Medium＋静的判定）: `rewrite` を
  Result 返却へ変更し、2つの不健全な分岐を廃した。(1) ワーカー
  生成失敗時に呼出側スタックで本体を実行する分岐（debug＋2MiB＋
  生成失敗で SIGABRT）。(2) ワーカー内 panic 時に原文を返す分岐
  （未変換の方言ソースが後段へ流れ、多重代入の first-wins 化や
  goto 形状の誤拒否を無言で起こし得る）。両分岐とも通常のロード
  エラーとして失敗する。生成失敗がその時点で正当な入力を拒否
  し得る点は否めないが、異常終了や無言の意味乖離より正しい失敗
  である。全呼出側（ロード可否判定、Vm::execute、require チャンク
  ローダ）がエラーを伝播する。wasm32 ではスレッド自体が存在せず
  生成は常時失敗するため、その場実行はフォールバック分岐では
  なくプラットフォーム構成として残し、API 文書に明記した
  （wasm のスタック溢れはホストへ見える trap であり、パーサの
  深さ上限が再帰を bound する。ネイティブの小スタック異常終了
  という S03 のハザードは wasm には存在しない）。回帰テストは
  子プロセスへアドレス空間制限を注入し、両 API が生成失敗の
  エラーで返ることを固定する（当初 dev-dependency で注入したが
  xtask のアーキテクチャ純粋性規則に反したため、シェルの
  ulimit 経由へ是正した）。
