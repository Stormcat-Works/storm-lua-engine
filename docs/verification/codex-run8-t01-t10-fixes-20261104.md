# Codex リリース前レビュー第4回（run8）T01〜T10 の修正（第309ラウンド）

候補スカッシュ `0fb6957` に対するリリース前レビュー（run8、2026-11-04）の
所見 T01〜T10 は、独立検証で **10件全件 CONFIRMED** となった（検証記録:
`hidden_files/codex-review/run8-verification-20261104.md`）。本ラウンドは
その全件の修正であり、候補の公開は引き続き停止する。基点は統合先端
`f1810dd`（製品コード `5707993` 相当）、コード先端は `083fc85`。
スカッシュ再構築・push・CI・公開工程は対象外（次段階）。

## 修正

- **T01（root_globals、通常経路）**: 代入先キー `t[(k)]` が R308 の S01
  位置分類をすり抜けた。実測で確定した PUC のタイミングは「プレーンな
  ローカルをキーとする代入先 Index は、括弧の有無によらず遅延読み
  （RHS 実行後にストアが消費）であり、大域化されたキーは RHS 前に
  実体化される」。分類が偶然全パイプラインの折り畳みに依存して残って
  いたのが漏れの構造である。修正: 位置分類の文書を実測どおりに是正し、
  バインド読みの括弧剥離を単一ヘルパへ統一、`Node::Assign` の代入先
  キー（括弧剥離後）を遅延読みとして、RHS・兄弟代入先部分木に書き手
  コールがある場合は大域化から除外した。回帰バッテリーは位置×括弧の
  直積へ拡張。
- **T02（expression-helper inlining、通常経路）**: ヘルパ本体の読みが
  インライン化で upvalue 再束縛コールを跨いだ（4→5）。修正: 読み取り
  時点インデックス（ノードごとの内包関数、束縛ごとの宣言関数）を新設
  し、コールサイトと同一関数で宣言された非パラメータ束縛の遅延位置
  読みが、書き込みうるコールを跨ぐ場合はインライン化を禁止する
  ゲートを追加した。ゲートは式ヘルパ書換え・単一使用ヘルパ書換え・
  リテラルコール折り畳みの3経路すべてに適用（同一機構のため）。
- **T03（single_use_forwarding、通常経路）**: 書き手判定が1段の名前
  ホップまでしか辿らず、高階呼出し（引数として渡された関数値の呼出し）
  経由の書込みを見逃した。修正: 書き手走査を推移化した（本文が直接
  書くか、関数境界を越えない呼出しが推移的に書くか。パラメータ等
  解決不能な被呼出しは保守的に「書く」側）。局所版の転送も同じ共有
  判定を使うため、報告の無かった局所兄弟形状も同時に直った（検証で
  確認）。引数感応な精密化（Option B）は採らず、保守的な閉包モデル
  （Option A）を採用。FULL のフットプリントは T03 帰属3ファイルに
  とどまり、B への切替は不要だった。
- **T04（signed_factoring、Smallest）**: 共有呼出し分類
  `call_may_read_fields` が「束縛に function_node がある名前」しか
  数えず、引数経由の高階呼出しをフィールドに触れるコールと認めて
  いなかった。修正: 組み込み以外の被呼出しはすべてフィールドに
  触れうると数える分類へ拡張し、因数分解の文グループ化では
  「読みがフィールドを含み、かつ文内にフィールドに触れるコールが
  ある」文でグループを分割する。直接のフィールドストア自体は
  分割理由にしない（ストアは文の値評価後に着地し、既存の分割検査が
  取り締まるため）。R308 S04 の固定形状（V3）は一致を維持。
- **T05（signed_factoring、Smallest、T04 と別機構）**: 投げうる
  キャリア読みが観測可能なコールより前へ巻き上がり、元の出力
  イベントが消えた。修正: 式の may-throw 構造述語（分析器の規則の
  写し）を新設し、キャリアが投げうる場合は「出現に先行する兄弟が
  観測可能効果（コール・順序効果。may-throw 自体は含めない）を
  持つ」文への出現をグループから除外する。
- **T06（方言書換え、通常経路、2形状）**: 複合代入の衝突固定モデルを
  `_ENV` 関与形へ拡張した。(A) 兄弟代入先が `_ENV` を再束縛する形:
  PUC はスキャン時点の環境へ大域ストアを凍結する（check_conflict）。
  書換えは対象の大域名を、凍結した `_ENV` 基底への Index ストアへ
  変換する（static_dedup フラグで重複排除と衝突ガードを駆動）。
  (B) `_ENV.x` の基底読みはスキャン時でなくストア時（upvalue 経由）
  であり、プレーンな `_ENV` 代入先が大域解決される場合に基底を
  遅延として印付けした。なお書換え形の二重ストア順序
  （`_ENV.x,_ENV.x=1,2` の後勝ち）は R02 以来の公認方言差であり
  バグではない（検証で切り分け済み）。
- **T07（方言書換え、通常経路）**: 名前のみの複合代入で、要素数が
  254 以上のとき書換えの一時レジスタが膨らんでいた。実測した境界:
  テーブル形式は要素が増えると膨らみ、逐次形式（一要素ごとに一時
  ローカルへ評価し、そのスロットが有効になる前に初期化する形）は
  253 で PUC と一致し 254 で一致して落ちる。修正: 要素範囲を式文
  パース時に直接数え（共有状態を使う skip_expr_list 経由はネストした
  引数リストで壊れるため不採用）、レジスタガード（有効ローカル＋
  要素幅のピーク＋形式別オーバーヘッド > 255 で書換え回避）と
  プレフィックス衝突検査の逐次形対応を追加した。境界の fallback
  側は T07b で揃えた（下記）。
- **T07b（フォールバック legality）**: 文脈自由な部分は残差では
  ない: 引数 254 個以上の単一コールは、いかなる文脈でも関数
  レジスタ＋引数＋1 が 255 レジスタファイルを超えるため、参照
  判定は常時拒否する。フォールバックの合法性ウォーカへこの上限を
  実装し、モジュール文書の残差記述を是正した（文脈依存の溢れは
  引き続き残差）。
- **T08（リンカ、通常経路）**: レジスタ見積りが各代入先を独立に
  数え、先行代入先が保持されるレジスタ（基底＋角括弧キー。ドット
  キーは定数）を後続の広いキー式の評価時に数えていなかった。
  修正: 左辺走査へ保持分の累積を導入。minify:false のロード不能
  生成と minify:true の不当な拒否がともに解消し、R08 の元形状の
  修正は維持した。
- **T09（リンカ静的ローダ、通常経路）**: 標準 require はモジュール
  関数へ（名前, ローダデータ）を渡す。生成グルーは可変長モジュール
  に名前のみ、それ以外には無引数で呼んでいた。修正: グルーと
  周囲 IIFE の呼出しを常に（名前, nil）へ統一した（preload 形
  ローダのデータは nil）。パック側の w6link オラクルも同じ標準
  意味論へ是正した（R306 の Q07 オラクル修正と同じ扱い）。
- **T10（フォールバック legality、3形状）**: 文書化済み残差の
  いずれにも該当しない文法受入の欠落。(a) `(x)=1`・(c) `a,f()=1,2`:
  文パーサが代入先を検証していなかったため、代入先は Name/Index
  ノードでなければならないとした（`(t).x` の括弧基底は正当な var
  として維持）。(b) `return 1and 2`: 字句解析が数値を分割していた。
  PUC の数値リーダの消費文字集合を実測で確定した（10進では
  16進数字の字 a-f/A-F、16進では更に指数の p/P を貪欲に取り込み、
  不正なら malformed number）。number_len が受理した直後にそれらの
  字が残る形を malformed として落とす。それ以外の字（`1or`・
  `1then` 等）はリーダも取り込まず、判定は拡張行列の全件で参照と
  一致した。印刷側の字句ガードは「ドットの後の名前開始」を
  再トークン化ハザードとして扱い、字句的出力が検証経路へ回る
  ようにした。
