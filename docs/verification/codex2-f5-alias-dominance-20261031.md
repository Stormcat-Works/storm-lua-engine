# 別名伝播の支配条件欠落（Codex 第2回指摘5、2026-10-31、ワーカー w9）

## 症状

`local x = f(2.5)` の後に `f = math.floor` と代入すると、コンパイラは後の値を
前の呼出へ伝播させ、`f` が未代入（nil）の時点で評価されるはずの呼出を
`math.floor(2.5)` とみなした。元は nil 呼出エラーで止まるプログラムが、
コンパイル後はエラーなく進んだ（第54サイクル c54-cases f05 で再現）。
消費側はトグル対象外の基盤段階である。

## 機構

`EffectAnalyzer` の apiAliases 固定点は、ルートブロック内で書き込みがちょうど
1 回のバインディングについて、その代入値のエイリアスをブロック全体へ登録していた。
代入がブロック内の読みより後に現れる位置関係（支配条件）を一切検査しておらず、
未来の代入が過去の読みへ伝播した。

## 修正

`root_block_alias_context` を導入し、両方のコンストラクタ（本体と参照実装）で
共有する支配ガードを追加した:

- ルートブロックの各直接文について、その文と先行する全ての文で読み取られる
  バインディングの集合（関数内の読みは定義文の位置に数える）を前方向に累積する。
- 候補の代入文とそれ以前の文に、対象バインディングの読みが1つでもあれば
  エイリアスを登録しない。
- チャンクレベル（関数外）の Goto／Label がブロック内のどこかにあれば、
  代入が飛ばされる可能性があるため、そのブロックではエイリアスを一切登録しない。

これにより、エイリアスは「代入が全ての読みを支配する」場合にのみ成立する。

## 検証

- 回帰テスト 2 件を追加（代入前の読みがある場合はエイリアスなし、チャンク
  レベルの goto がある場合はエイリアスなし。既存の「代入後にのみ読む」ケースは
  エイリアス維持を継続確認）。同クレート 121 件合格、ワークスペース全件
  1,457 件合格・失敗 0、clippy 警告 0。
- c54-cases f05: 修正後、通常・safe の両モードでコンパイル後も元の時点で
  nil 呼出エラーになる（エラーメッセージ中の名前はリネーム後の識別子）。
- Tier FULL（基点 `82fab7e6c`＝FULL-VERIFY-TIP）: 全 4 条件で identical=4,072
  （map 条件は identical=4,071＋expl-only=1）／hard=83／map-core=0、
  ステータス不変（ok 4,128／error 27）。hard は支配条件で失格した
  （以前は健全でなく登録されていた）エイリアスの保守化によるもので、
  生成コード合計は条件あたり +3,574 文字。差分のある 84 ファイル全件を
  diffexec で実行比較し、82 件は base／head でトレース集合が一致。
  残り 2 件（35a54819…、9a0425a2…）は同一バイナリの再実行でもトレースが
  変わる自己不安定ファイルであり、トレース比較では分類できない
  （コード差分自体はエイリアス喪失による保守化の形）。
