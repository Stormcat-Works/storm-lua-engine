# 候補B（MemberReadGuard の ChainRead 抜け）と指摘2ただし書きの完結 — 検証記録

対象: `crates/storm-lua-minify/src/passes/immutable_values.rs`（MemberReadGuard／置換収集）
担当: w9 第62サイクル

## 候補B（w6 第54サイクル項目3で確定）

```lua
local t = { x = { y = 1 } }
local inner = t.x
local a = t.x.y
local function f() return t.x.y end
inner.y = 99
return a + f()   -- 素: 100 / 最適化: 2
```

第226ラウンドの MemberReadGuard は閉テーブル認定で「ルート束縛への
メンバー書込み」と「ルート自体の値使用」だけを見ていた。中間
テーブル `t.x` が別名ローカル・引数・コンストラクタフィールド・
戻り値へ値として escape すると、escape 先経由の書込みは別束縛を
ルートとして記録されるため、`t` が閉テーブルと誤認定され、書込み
後の `t.x.y` の読みが古いキャリアへ置換された。

## 修正（候補B）

- 走査（`scan_member_uses`）で、値位置またはメソッドベース位置に
  現れる Index チェーンを escape として記録する。チェーンは
  `decompose_chain` で（ルート束縛列, ステップ列）へ分解し、
  ステップキーは文字列キーを復号して綴り差を吸収し、数値キーは
  値で正規化する（`t.x` と `t["x"]` は同一キー）。分解できない
  チェーンはルート全体を不証明として記録する。
- キャリア側の検査（`expression_is_time_invariant`）では、読み
  チェーンの真の接頭辞が escape 済みチェーンと一致したら不受理
  とする。escape した値そのものの読み（同一性は書込みで変わら
  ない）は引き続き許可される。escape した別名自体をキャリアと
  する置換（例: 関数内の `t.x.y` を `inner.y` へ）も、別名が
  同一テーブルを恒常的に指すため健全であり、許可される。
- 回帰テスト4件を追加（別名 escape、引数 escape、escape した値
  自身の読みは引き続き再利用されること、を含む）。

## 指摘2ただし書きの検証完結

第226のガードが阻止するのは「メンバー書込みがルートを毒する」
形であり、ガードを通過する基底経由のターゲット置換が未検証
だった。検証の結論は次のとおりで、ターゲット置換は起きない。

1. 置換収集（`collect_replacements`）は、関数内の Assign／
   Funcstat のターゲットノード自体を二度と置換しないよう硬化
   した（従来はキー一致すればターゲットも置換対象だった）。
   ターゲットの子（基底チェーンとキー）は値位置であり、そこ
   の置換は従来どおり許される。単体テスト2件で、代入ターゲット
   と Funcstat ターゲットが収集から除外され、読みだけが残る
   ことを固定した。
2. ガード側の被覆: ターゲットがキャリアキーと一致し得るのは
   Index ターゲットのときだけであり、その書込みは基底ルートを
   必ず毒する（閉テーブルなら `scan_member_uses` の write_roots、
   組込みルートなら `mutated_builtin_roots` の target_bases が
   捕捉する。メソッド定義・and/or 基底・括弧も走査対象）。
   したがってガードを通過したキャリアについては、一致する
   ターゲットが存在しない。
3. 敵対的形状の実行確認（diffexec）: キー位置への置換
   （x01）、メソッド定義による毒化（x02）は素と一致した。
