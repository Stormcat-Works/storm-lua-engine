# Codex 第3回指摘1（入れ子代入の書換え panic）の修正 — 検証記録

対象: `crates/storm-lua-vm/src/dialect.rs`（第210ラウンドのロード時方言変換）
担当: w9 第60サイクル

## 指摘（Codex 第3回 #1、High）

```lua
a,a=function() b,b=1 end
```

を `Vm::execute` で実行すると、方言変換 (a)（多重代入の last-wins 化）が
`dialect.rs:69` で `slice index starts at 24 but ends at 15` と panic した
（第59サイクルの再現で両先端とも確定）。

## 根本原因

`collect_assign_edits` は全ブロックの編集を返す。関数式の内側にある代入は、
その関数式を含む外側の代入文のバイト範囲に**含まれる**ため、編集同士が
入れ子になる。適用ループは編集が互いに素である前提で開始位置順に接合して
おり、内側の編集（開始位置が外側の終了位置より前）を処理する段で
`current[pos..start]`（pos > start）が panic した。

## 修正

- 編集を開始位置昇順・同点では終了位置降順に並べ替え、適用済みの外側の
  編集に含まれる内側の編集はその走査では飛ばす。
- (a) 段全体を不動点まで反復する（上限64回）。内側の代入は外側の置換
  テキストに原文のままコピーされるため、次の走査で書き換わる。置換は
  新しい重複代入を生まないので反復は終了する。
- 回帰テスト2件を追加（正確な再現形、二重入れ子の不動点到達）。

## 付随修正（同ラウンド・同領域）

回帰テストの作成中に見つけた隣接欠陥を同根として併せて直した。
`skip_expr_list` の空リスト終端キーワードに `function` が含まれており、
`return function() ... end`（式を持つ return）を空の return と誤認して
走査全体が失敗し、そのチャンクでは方言変換が一切発火しなかった。
`function` を終端リストから外した（妥当な Lua では return の後に
function 文は続かず、不正な入力は従来どおりパース失敗で変換を諦める）。
回帰テスト1件を追加。

## 検証

- dialect 単体テスト: 21件 → 24件、全通過（既存21＋新規3）。
- storm-lua-vm クレートのテスト全通過。ワークスペーステスト 1,584 件全通過。
- 第59サイクルの再現スイート（c59-cases、65セクション）を修正前後で比較:
  変化は r3-01 のセクションのみ（panic rc=101 → `vm: completed`）。
  コンパイラ系・link 系を含む他の64セクションはバイト一致。
- Tier INVARIANT として統合する。根拠: 変更は storm-lua-vm のロード時
  変換のみで、コンパイラの生成コード／Source Map には構造上触れない
  （コンパイル経路は `dialect::rewrite` を呼ばない）。コーパスの累積
  比較は次回 Tier FULL ラウンドで FULL-VERIFY-TIP からまとめて行う。
