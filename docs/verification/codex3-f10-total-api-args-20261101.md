# Codex 第3回指摘10（TOTAL_API 引数検査の残存漏れ）の修正 — 検証記録

担当: w9 第62サイクル

## 指摘（Codex 第3回 #10）

第199ラウンドの TOTAL_API 引数検査が不完全で、以下が依然として
「投げない」と判定され、呼出しが除去・移動され得た:

```lua
local a = math.atan(1, {})   -- 素: bad argument #2 to 'atan'
local b = math.max(1, "2")   -- 素: attempt to compare number with string
```

- atan は第2引数も検査する（省略可能な引数だが、nil でなければ
  `luaL_optnumber` が型検査する）。旧判定は単項メンバーとして
  第1引数しか見ていなかった。
- max/min の引数比較は `lua_compare` で行われ、数値強制は働か
  ない。旧判定は「数値文字列は数値として可」という引数検査の
  モデルを流用していたため、数値と文字列（数値文字列を含む）
  のペアを取りこぼした。

## 修正

- atan: 第1引数に加え、固定引数が2個以上あり第2引数が静的に
  nil でない場合は、その非数値性も検査する。
- max/min: 全固定引数の非数値検査に加え、静的に数値と判明する
  引数と静的に文字列と判明する引数が混在したら投げ得るとする
  （文字列同士・数値同士は従来どおり可）。静的数値／文字列／
  nil の判定ヘルパを追加した（括弧と単項マイナスを透過）。
- 単項メンバー（floor 等）が追加引数を無視する扱いは不変。
- 回帰テスト3件を既存の `total_api_argument_tests` に追加
  （atan 第2引数、max/min の数値・文字列混在、単項の追加引数
  無視の維持）。
