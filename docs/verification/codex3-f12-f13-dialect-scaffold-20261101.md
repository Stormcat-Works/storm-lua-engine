# Codex 第3回指摘12・13（生成足場のスコープ／予算／名前）の修正 — 検証記録

対象: `crates/storm-lua-vm/src/dialect.rs`（多重代入の書換えの足場設計）
担当: w9 第60サイクル

## 共有する根

2件とも、書換えが導入する足場（一時変数）の設計に起因する。従来は
値・アドレスごとに1本の一時変数を導入していた。

## 指摘12（Medium）: スコープと予算

- 生成一時変数が文のスコープに残るため、そのスコープへ入る goto が
  Lua 5.3 の規則で load error になった（r3-12a）。
- 文を繰り返すと一時変数が累積し、200本のローカル上限を超えた
  （`a,a=1,1;`×101、r3-12b）。

## 指摘13（Medium）: 一時名の衝突検査範囲

衝突回避が接頭辞サフィックス 0..=64 だけを調べていたため、65 以上を
使っているプログラム（`__stormvm_t65`）でユーザーの大域変数を一時変数
が遮蔽した（r3-13: 7 → 0）。

## 修正（一時変数の設計そのものの変更）

- 書換え対象の文全体を `do ... end` で包む。足場のローカルは包んだ
  ブロックの中だけに生き、後方 goto がそのスコープへ入ることは
  文法上なくなる（前方 goto は従来どおり書換え前の文へ向かう）。
- アドレスと値を2本のテーブル一時変数へ集約する
  （`local A = {addr...}; local V = {rhs...}`）。文あたりの追加
  ローカルは文の長さによらず最大2本。テーブルコンストラクタの調整
  （末尾の多値式の展開・不足分の nil 埋め）は多重代入の調整と一致し、
  ストアは `A[i]`/`V[i]` を逆順に読むため意味論は従来と同一。
- 衝突回避は、この2本の名前（`{接頭辞}a` / `{接頭辞}v`）そのものだけを
  チャンク全体の名前集合と照合し、衝突する限り接頭辞を伸ばす
  （固定された数値窓を調べる方式を廃止）。

回帰テスト4件（goto を跨ぐ書換え、101文の予算、22ターゲット文での
`__stormvm_t65` 保存、一時名がユーザー変数と衝突しないこと）を追加。

残る制約（記録）: 包む対象の文が置かれたスコープ自体が既に上限近くの
ローカルを持つ場合、2本の追加で上限を超え得る。これは従来（無制限に
一時変数を追加）より厳密に改善された既存制約であり、退行ではない。

## 検証

- dialect 単体テスト: 27件 → 31件、全通過。
- c59 再現スイート（65セクション、前ラウンド結果との差分）: r3-12a と
  r3-12b が load error から `vm: completed` へ、r3-13 の rewritten が
  `[0]` → `[7]` で原文と一致。他の差分は新しい足場による書換え後
  バイト数（len メタ情報）のみで、実行結果は不変。
- ワークスペーステスト 1,602 件全通過。
- Tier INVARIANT（VM ロード時変換のみ。連続 INVARIANT は第232ラウンド
  の Tier FULL を挟んで本ラウンドが1回目）。
