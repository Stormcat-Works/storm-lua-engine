# Codex 第3回指摘3（plain 形の依存書込み順序）の修正 — 検証記録

対象: `crates/storm-lua-minify/src/passes/immutable_values.rs`（不変値再利用の依存判定）
担当: w9 第62サイクル

## 指摘（Codex 第3回 #3、残存 plain 形）

```lua
a = 1
b = a + 1
a = 2
local function f() return a + 1 end
return b, f()
```

素の実行は `(2, 3)` だが、最適化後は関数内 `a + 1` がキャリア
`b`（定義時点の値 2）に置換され `(2, 2)` になった。テーブル変種は
第226ラウンドの MemberReadGuard で阻止済みだが、plain な依存の形が
残っていた。再現は第59サイクルの r3-03（4構成すべてで乖離）。

## 根本原因

キャリア式の依存束縛は「書込み回数が最大1回」
（`dependencies_are_single_write`）だけで受理されており、書込みの
位置と実行タイミングを見ていなかった。依存への単一書込みが

- キャリア文より後のトップレベル文にある、
- キャリア文自身の別ターゲットである、
- 関数本体内にあり任意の呼出し時点で実行され得る

のいずれかだと、定義時点の値と置換先での再評価の値が食い違う。

## 修正

- ルートブロックに対する各ノードの位置（所属するトップレベル文の
  序数と、関数境界を越えているか）を一度だけ計算する
  `RootPositions` を追加。
- 依存束縛の単一書込みは、その書込みノードがキャリア文より前の
  トップレベル文に属し、関数本体内にない場合にのみ受理する。
  置換先はキャリア束縛のスコープ内（＝キャリア文の後）にしか現れ
  得ないため、その時点で依存の値は定義時点と一致することが保証
  される。
- ルートブロック内（関数本体外）に `goto`/`label` がある場合は
  文順序の議論が崩れるため、単一書込み依存を一律に受理しない。
- 回帰テスト5件を追加（後方書込み、関数内書込み、キャリア文自身
  のターゲットによる書込み、goto がある場合の不受理、および前方
  書込みでは引き続き再利用が効くことの正例）。

## 検証

- immutable_values 単体テスト: 13件 → 18件、全通過。
- ワークスペース全体のテスト: 全スイート合格（失敗0）。
- c59 再現スイート（65セクション、base = 第241ラウンド先端）との
  差分は r3-03 の4構成のみで、全て意図した方向（最適化結果が
  `(2, 2)` から素の `(2, 3)` に一致）。
- Tier FULL: コーパス 4,155 ファイル×4構成＝16,620 行が base／head
  とも SHA-256
  `743431aa4bb3142c3661c78dfdbf63219052704c8d763fbd35cda85d73279be7`
  でバイト一致（fallback 0）。強化した時間規則で実コーパスの再利用
  は一切失われなかった。
