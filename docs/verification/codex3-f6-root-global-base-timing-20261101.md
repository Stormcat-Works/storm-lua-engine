# Codex 第3回指摘6（root-local globalization の基底タイミング）の修正 — 検証記録

対象: `crates/storm-lua-minify/src/passes/root_globals.rs`
担当: w9 第62サイクル

## 指摘（Codex 第3回 #6）

```lua
local t = {}
local function f() t = {} return 1 end
t.x = f()            -- 素: 新しい t へ書く（基底は保存時にレジスタ再読）
return t.x           -- 素: 1 / 最適化: nil
```

メンバー代入の基底が包囲関数のローカルなら、保存時点でレジスタが
再読されるため、右辺の呼出し中に起きた再束縛の後のテーブルへ
書かれる。ところが root ローカルのグローバル化で基底がグローバル
になると、基底は右辺より前に実体化され、書込みが古いテーブルへ
落ちる。w6 第54サイクル項目3で、複数ターゲット形（e06）や3ター
ゲット形（m14）も同じ根であることが切り分けられていた。

## 修正

グローバル化の対象から、次の両方を満たす root ローカルを除外する:

- 関数本体の外にあるメンバー代入ターゲットの基底として使われて
  いる（レジスタ再読の意味論が適用される位置）。
- その窗口で再束縛され得る: 関数本体内に書込みがある（右辺の
  呼出しや即時実行関数で実行され得る）、または同じ複数ターゲット
  代入文の前方の名前ターゲットとして現れる。

関数内でのみ基底として使われるローカルは upvalue であり、グロー
バルと同様に実体化されるため、従来どおりグローバル化される。
回帰テスト4件を追加（関数内再束縛で保持、同文再束縛で保持、
再束縛なしでは引き続きグローバル化、関数内でのみ使う場合は
引き続きグローバル化）。
