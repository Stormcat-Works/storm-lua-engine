# Codex 第3回指摘8（_ENV 代入先の喪失）の修正 — 検証記録

対象: `crates/storm-lua-vm/src/dialect.rs`（多重代入の書換えのストア順序）
担当: w9 第60サイクル

## 指摘（Codex 第3回 #8、High）

```lua
local old=_ENV
_ENV,x,x={},1,1
return old.x,x
```

原文（PUC）は `[1, nil]`、書換え後は `[nil, 1]` になった。PUC は代入の
ストアを逆順に行うため、x へのストアが _ENV の再束縛より先に起き、
旧環境へ書かれる。書換えは出現順にストアしていたため、_ENV の再束縛が
先に起き、x のストアが新しい環境へ行った。

## 根本原因と修正

方言変換が変えるべきなのは「重複ターゲットの最終値」だけだが、出現順
ストアは異なるターゲット間の相対的なストア順序まで変えていた
（_ENV 再束縛の位置、`__newindex` の発火順序などとして観測可能）。

修正: アドレスと値の評価は従来どおり出現順に一時変数へ行い、ストアは
PUC と同じ逆順に行う。ただし重複ターゲットは最後の出現だけをストアし
（それ以前の出現は飛ばす）、最終値の last-wins を保つ。これにより
異なるターゲット間のストア順序は PUC と一致し、重複の解決だけが
方言として変わる。モジュール冒頭の説明もこの意味論へ更新した。
回帰テスト1件（_ENV 再束縛形）を追加。
