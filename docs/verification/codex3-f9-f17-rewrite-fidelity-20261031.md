# Codex 第3回指摘9・17（書換えテキストの忠実度）の修正 — 検証記録

対象: `crates/storm-lua-vm/src/dialect.rs`（多重代入の書換えテキスト構築）
担当: w9 第60サイクル

## 共有する根

2件とも、置換テキストを `String` として構築しトークン断片を文字列化して
コピーしていたことに起因する。置換テキストの構築そのものの忠実度の問題
として同一ラウンドで直した。

## 指摘9（High）: 生バイトの破壊

文字列リテラル内の非 UTF-8 バイト（例: 0xFF。Lua の文字列はバイト列）が
含まれる文を書き換えると、`slice_tokens` の `String::from_utf8_lossy` が
そのバイトを U+FFFD（EF BF BD）に置き換え、意味が変わった
（r3-09: `string.byte(a)==255` の分岐が反転）。

修正: 編集・置換テキストを `Vec<u8>` へ変更し、断片（右辺・base・キー）は
元のバイト列をそのままコピーする。生成する足場テキストは ASCII のみ。

## 指摘17（Medium）: エラー行位置のずれ

モジュール冒頭の契約は「改行は追加・削除しないため行番号は保存される」
だったが、再構成されるターゲット並びは元のターゲット範囲内の改行
（`t.\nx` 等）を含まず、文の改行数が減って後続コードの行がずれた
（r3-17: エラー行 4 → 2）。

修正: 置換ごとに、元の文の範囲にあった改行数と置換テキスト内の改行数を
数え、不足分を文の境界である末尾（生成したストアの後ろ・末尾の空文の前）
へ改行として補う。チャンク全体の行数が保存される。
