## 実装内容

### 1. 分類のためだけのAPI名の文字列生成を削減

`EffectAnalyzer`が`math.sin`や`input.getNumber`等を判定するとき、根の別名と最後のmemberを借用したまま分類する。従来は呼出のたびにmemberの復号と完全修飾名のString化を行っていた。エスケープ・長括弧・深いmemberは必要な場合だけ従来と同じ復号/結合を行う。

公開の`resolve_builtin_reference`は引き続き完全なStringを返す。PURE/TOTAL/副作用の規則、shadowing・後続write・関数summary・変更可能なstable_readsの意味は変更しない。別名やsummaryを永続cacheして古い状態を使う処理ではない。

### 2. AST走査の不要なsnapshot割当を削減

子を持たない名前・リテラル・制御葉では、走査callbackを呼ぶ前に使い捨てのノードを複製しない。単項/二項の通常Lua演算子は静的な表記を保持し、子のIDが実際に変わった場合だけ新しい所有Stringを作る。

callbackが親のslotを参照・変更する契約は維持する。子IDが変わらない場合に古い親を勝手に復元せず、変わる場合には元snapshotを基準に置き換える。低レベルAPIから渡された未知の演算子表記も正規化せず、そのまま保持する。

### 3. 短縮名の小さな確保を削減

頻出する1文字の短縮名は、既存の正準alphabetから借用する。長い名前や外部へ返すStringは必要に応じて所有する。名前の候補順、予約語の除外、captureと寿命の競合判定、binding順、public mapping/iteratorの型は変えていない。

### 4. マップの位置変換・識別子保存

生成順に並ぶアンカーや同じ行の元位置について、直前のUTF-16変換区間を再利用する。非単調なジャンプは二分探索へ戻り、範囲外やUTF-8文字途中は従来どおり拒否する。固定した同じ原文の中だけで使うcursorであり、次のコンパイルへ残るcacheではない。

大きな字句短縮結果では、繰り返される同じ識別子の文字列storageを共有する。**異なる出現位置のorigin IDやspanを統合するものではない。** 小さい入力は余計な辞書処理を避け、名前の出現順・精度・Unknown区間を維持する。
