# コンパイル CPU: api-alias の空集合候補を構築なしで計測（第92サイクル、Tier INVARIANT）

対象: `crates/storm-lua-minify/src/passes/api_aliases.rs` の選択探索
（`run_with_analysis`）が呼ぶ `measure_candidate`。第92サイクルの計装で、
レイアウト構築（std-nomap 全コーパス、逐次単一プロセスのプローブ会計で
17.20 秒）の 92% が joint-api レイアウトであり、その中身は貪欲探索の
試行ごとの候補構築 175,460 回（`apply_alias_set` 6.68 秒＋
`measure_renamed_size` 6.69 秒）だった。Ast の clone 自体は全面 Arc 共有で
主因ではない（領域内の values 深コピーは 17,231 回・18,439,637 要素、
interner 深コピーは 180,900 回・15,888,198 エントリで、いずれも候補構築に
付随する量）。

## 変更

`measure_candidate` で、選択集合が空の場合に限り候補を構築せず、
source の renamed size を直接計測して `(len, None)` を返す（結果は
従来どおり集合キーでメモ化する）。空集合が勝った場合のツリーは、
メモ化済み集合に対する既存の再構築経路（`make_candidate`）が同一の
ツリーを返す。

## 不変性の根拠

空の選択に対する `apply_alias_set` は純粋な構造クローンである:

- `clone_rewriting` は別名マップにキーが含まれる組込み参照だけを
  置換する。空マップでは置換は一切発火せず、全ノードが
  子を再帰的にクローンした同一ノードとして push される。
- 選択が空なら定義文は生成されず（`selected.is_empty()` の早期 return）、
  alias 名の `fresh()` 呼出も無い。interner は `inherit_ast` の共有のまま
  変わらない。
- したがって候補ツリーは source と構文・interner が同一であり、
  ルートからの走査だけを読む `measure_renamed_size` の値は一致する。
  ローカライズ形でも空集合は常に予算可行で、計測経路は同じである。

実証（計装プローブ、全コーパス）: 空集合の構築は 8,724 回
（alias 実行あたり 1 回）で、直接計測値との不一致は 0 件だった。
この同一性は単体テスト
`empty_candidate_length_equals_source_renamed_size`（両 variant・
4 ソース）でも固定した。空集合が初期選択になる形の振る舞いは
`empty_selection_reconstructs_a_plain_renamed_tree` が固定する。

## 決定論カウント（計装プローブ A/B、同分岐元）

- 候補構築（`make_candidate` 呼出）: 175,460 → 168,707 回
  （−6,753 回）。差引は、空集合が実際に勝って再構築経路で作り直された
  1,971 回分を含む。消えた構築は 1 回あたり平均約 1,490 ノードの
  アリーナ再構築＋interner コピー＋割当である。
- プローブ行（std-nomap）は両側ともベースライン TSV と一致。

## 本サイクルの計装が残した候補順位（未実装）

レイアウト構築の残部と変種選択側の rename 計測
（`measure_renamed_size` 全体で 406,543 回・13.40 秒、対象ノード総数
404.7M）の順位は PROGRESS-w7 第92サイクル節に記録した。要点:

1. api-alias 探索の試行構築＋計測そのもの（残り約 168,707 回）。
   構築なし計測の一般化は rename plan の正確な増分計算を要し、
   選択の一致証明が前提。
2. `measure_renamed_size` の同一アリーナ版への再計測が全体の
   38.8%（157,719 回）。健全なメモ化には NodeArena／Interner の
   世代カウンタ（全変更チョークポイントでの増分）が前提。
3. barrier-relaxed 合成の毎ジョブ試行（8,719 回・0.88 秒、生成
   レイアウトは 10 件のみ）。必要条件ゲートは事前走査自体が
   パス走査に近く経済性が薄い。
