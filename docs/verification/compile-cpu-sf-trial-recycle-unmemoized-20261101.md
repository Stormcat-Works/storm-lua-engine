# コンパイル CPU: signed-factoring 試行アリーナ再利用＋非挿入計測（2026-11-01、w7 第98サイクル）

## 変更

- 実装: `21761dc`（第97サイクルの試行アリーナ再利用）＋`c61eadb`（非挿入計測経路と scratch stamp ガード）。分岐元 `a600e55`（第259ラウンド）から作成し、統合前に現行先端 `7e0d28a`（第260–268ラウンド）へ rebase した。対象は `crates/storm-lua-minify/src/passes/signed_factoring.rs` と `crates/storm-lua-minify/src/scope_rename.rs`。
- signed-factoring の候補計測は、ラウンド内で origin-less 試行アリーナ（`trial`）とキー用アリーナ（`key_scratch`）を再利用する。構築は共有バッファの上で行い、計測後に undo ログ（上書きしたスロットの旧値）で復元＋末尾 truncate することで、次候補は fresh clone と同一状態から始める。勝者（tracked）経路は不変で、構築本体 `build_signed_candidate` を試行・勝者で共有する。再利用の前提として、ラウンドの `scratch` が再利用開始時点から動いていないこと（長さ・arena 世代・symbol count の stamp 一致）を毎回確認し、不一致なら fresh clone に戻す（候補ループは `scratch` を読むだけなので、発火しない見込みの防御）。
- 試行の計測は、サイズ計測メモへ挿入しない経路 `measure_renamed_size_unmemoized` で行う（下記監査）。勝者・ベースライン等の通常計測は従来どおりメモ経由。

## 第97サイクルの失敗とその根本原因

- 第97サイクルは再利用のみを実装し、不変性検証（テスト・FULL 相当ゲート）は全て通過したが、事後の決定論測定（全アリーナ detach カウンタ）で detach 総量が base 240,157 回／289,650,722 要素 → 243,598 回／295,032,140 要素と増加し、マージしなかった。
- 原因は第93ラウンド（R257）の計測メモが、計測したバッファの `Arc` clone を保持することにある。メモ経由で計測された直後の試行バッファは共有状態にあり、再利用側の復元（undo ログの最初のスロット書戻し）がバッファ全体の detach を、clone 時（scratch 長）ではなく構築後長（候補生成物が append された分だけ長い、平均 +256 要素／候補）で払っていた。detach は「保存される原木から候補木を実体化する」コストであり、再利用はそれを clone 時から復元時へ移すだけだった。

## 計測メモの契約監査（健全性前提）

「試行バッファについてはメモへ挿入しない計測経路を用意する」ことの健全性を、`scope_rename.rs` のメモ実装と全利用箇所のコード読みで確認した。

- **計測の純粋性**: `compute_renamed_size` は `&Ast` のみを取り、`rename_plan`（共有参照からの resolve と局所データ構造）と `measure_size_with_names`（純粋な走査）からなる。`Interner` は `Arc` フィールドのみで内部可変性を持たず、計測経路は文字列を `get` で読むだけである。計測値はサブツリーの構文と、そこから到達可能な文字列のみの関数である（R257 のメモ文書自身の前提でもある）。
- **メモの値透過性**: メモ hit が返すのは、同一 stamp（values バッファ同一性・arena 世代・strings バッファ同一性・symbol count）で過去に挿入された値である。第93サイクルの監査済み不変条件（構文変更は全て `NodeArena::values_mut` を通り世代を進める／起源のみの変更は計測に影響しない／interner は append-only で既存 id の文字列は不変・成長は symbol count が捉える）により、同一 stamp は同一サブツリー構文・同一参照文字列を意味し、再計算は挿入値と必ず一致する。したがって任意の呼出し列について、返値の列はどの呼出しがメモを経由するか（hit／miss／非経由）に依存しない。挿入の省略は返値を変えず、再計算コストだけを変える。
- **世代・symbol count の進行**: 世代を書くのは `values_mut` のみ、interner を変えるのは `intern`（`&mut`）のみで、メモ関数（`renamed_size_memo_get`／`put`）は `&Ast` しか取らず arena・interner を一切書かない。挿入の有無は世代・symbol count の進行に影響しない。
- **排出タイミング**: `put` の上限到達時の全消去（バッファ対 64・総サイズ 32,768）と `get` の stamp 不一致時のエントリ消去は、どちらもメモ内部状態（`entries`／`total_sizes`）だけを変える。これらに触れるのは `scope_rename.rs` 内の get／put のみで、外部からの参照はない（crate 全体の grep で確認）。排出の前倒し／先送りが変えるのは将来の hit／miss の別だけであり、値透過性により返値には影響しない。
- **呼び出し側の調査**: `measure_renamed_size` の外部呼出しは22箇所、全て返値の `usize` のみを消費する（関数が値で返す以上、他の出力チャネルは存在しない）。signed-factoring 内の呼出しはベースライン（`source` 対象）と試行のみで、試行バッファを他の誰も計測しない。
- **残る観測可能チャネルは pin のみ**: `put` が保持する `Arc` clone は、計測されたバッファの寿命と strong count を変える。これは値ではなくコスト側の効果である（`Arc::make_mut` の detach は内容を同一に複写し、strong count 自体は節点値から観測できない）。第97の反転はこのチャネルによるもので、本変更は試行バッファについてこのチャネルを断つ。なお `get` は一時的な `Arc` clone を関数の戻りまでに手放すため pin を生まないが、非挿入経路では get 自体も行わず、試行計測をメモに対して完全に無状態にする。

以上により監査は立つ。加えて回帰テスト `renamed_size_unmemoized_agrees_and_does_not_pin_the_buffers` で、非挿入経路が (a) メモ経由と同値を返し、(b) 呼出し前後で values／strings 両バッファの strong count を変えない（＝保持しない）ことを固定した。

## 決定論カウント（事前登録判定）

第97と同一の計装（`NodeArena::values_mut` に全アリーナ合算の detach カウンタを挿入した gsprobe、std-nomap 全コーパス、逐次単一プロセス）で、統合前に base／head を測定した。判定条件は事前登録どおり「detach 総量（回数・要素数）が base より実際に減少しなければ、不変性検証が全て通ってもマージしない」。

- 分岐元 `a600e55` での対: base 240,157 回／289,650,722 要素（第95 census・第97 base と完全一致＝計装の妥当性）→ head 222,581 回／256,150,432 要素。**−17,576 回（−7.3%）／−33,500,290 要素（−11.6%）**。出力行は両側バイト同一（ソート済み SHA-256 `30ec6bd25d89f5fb8b3d3b95b9067a3afcebac61cd4b60866afbde682536af63`）。
- rebase 先 `7e0d28a` での対（最終形）: base 239,341 回／288,648,040 要素 → head 221,768 回／255,152,067 要素。**−17,573 回（−7.3%）／−33,495,973 要素（−11.6%）**。出力行は両側バイト同一（ソート済み SHA-256 `a98b16ff7a1a80b000577529177e0ed4391e533608f08e3be9d579aea84159c9`）。
- 削減の内訳は主に trial_originless 桶（第97切り分けで 21,017 detach／38,688,228 要素）のうち、ラウンド毎の初回候補分を除く大半が消滅したことによる。
