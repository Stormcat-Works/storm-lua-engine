# v0.3.1 コンパイル待ち時間の追加削減 — 2026-10-05

**API別名候補のサイズ評価で改名ASTを作らない方式、小さな整数の表記生成、重複する由来関係の照合を改善した。** 実装commitは`627f8d152ebba29f555b9d12668e408a80fc386d`。基準は直前の検証済み`353522c`であり、前の解析共有や依存解析の効果を重ねて今回の短縮率に数えない。

全探索4,054成功原文の平均時間は、今回の同一環境比較でMapなし **8.2%短縮**、Mapあり **6.8%短縮**。Mapあり/なしの平均時間比は **1.135倍**だった。これは有限のコーパス平均で、最大1.2倍の達成判定ではない。

**最大1.2倍、可能なら1.1倍という目標はまだ未達。** 固定した成功40シーン中、1.2倍以下は10、1.1倍以下は0。最大の中央値比は4.706倍。通常の処理時間を遅くして倍率を改善したり、由来情報を減らしたりする処理は入れていない。

## 1. 実装

### API別名候補の改名は、採用したものだけ

これまでは別名集合の候補を試すたびに、別名適用後のASTをさらにscope renameしたASTへ作り直して、その文字数を調べていた。今回、既存の正確な`measure_renamed_size`で候補を比較し、採用した名前割当だけを最後に適用する。Mapなしでは採用済みの構文を再利用し、Mapありでは採用した別名集合を元の由来付き構文へ適用してから改名する。

候補の集合、順序、4-roundのremove/add処理、同点の扱い、短縮名の割当と原文の対応は維持する。名前短縮そのものを省略したのではなく、不採用になる改名後ASTの構築をなくした。元の完全な候補生成を独立したtest-only参照として残し、全67パスの入力・変換後・由来欠落・復元状態で、AST/SymbolId/NodeId/マップまで比較した。

また、別名で書き換える際、変更されない入力ノードを二重にcloneしていた箇所を1回のsnapshotへ減らした。入力は別のimmutable ASTなので、mutableな親ノードを途中で抜き取る変更ではない。

### 小さな整数の表記を、浮動小数の桁列から作り直さない

binary64で整数と判定され、signed 32-bit範囲に収まる値は、正確な整数formatterを使う。この範囲では従来の固定小数点表記と一致する。これまでの`1e5`・`1e6`の例外、負の0、非有限値、範囲外の数値、整数/小数の意味論は維持する。

既存の浮動小数formatterを使う独立参照との比較に加え、65,536個の疑似ランダムi32、端点と隣接値、通常の整数を確認した。scope renameや候補探索の結果を変えて速くしてはいない。

### 由来関係がすでに含まれる場合の再走査を避ける

由来をコピーした結果、寄与元の関連範囲や型付き関係が、すでに同じimmutable vectorまたは完全一致のprefixとして存在する場合がある。これは明示的な同一性・包含の証拠なので、追加だけを行う間に、既知の要素を毎回全件検索する必要はない。

この証明がない場合は元のスカラー比較を維持する。新しいhash tableを各ノードに作る案ではない。主な元位置、順序、各関係のrole、重複の扱い、理由の件数は変えない。shared/serde復元/prefix/異なるroleを独立した従来処理と比較した。

## 2. 採用しなかった試行

WASM上のSHA-256 backendと、JSON内の固定enumタグ・ハッシュのhex表記にも計測を行った。どちらも公開形式を維持した試行だが、採用に足るmap時間改善を確認できなかったので元へ戻した。

- `sha2`の既存compact scalar backendは、字句短縮mapで約7〜13%遅い観測になった。既存backendを維持し、依存・featureの変更は残していない。
- enumの定数JSON表記とhex formatterの置換も、字句短縮mapで有効な改善を示せなかった。独自の重複encoderを残さず、patchと生の試行結果を検証領域へ保存した。

これらの試行の値を採用実装の改善率へ足したり、失敗結果を消して選別したりしない。小さな整数の数値表記改善と、マップ上のhash表記の試行は別の変更である。
