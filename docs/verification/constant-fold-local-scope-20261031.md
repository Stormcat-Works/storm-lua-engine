# 検分: 定数畳み込みの接合がローカル宣言のスコープを広げる問題（w6 第54サイクル）

## バグ

`literal_folding`（constant-folding）の制御フロー簡約は、定数選択した `if`／`else`
本体を本体ブロックそのものへ置換し（`selected_body`）、親ブロックの平坦化が素の
`Block` 文を親へ接合する。第223ラウンドはトップレベル `return` を含む本体について
`do` で包むよう直したが、**トップレベルでローカルを宣言する本体**は接合されたまま
だった。接合は宣言のスコープを囲みブロックの残り全体へ広げるため、後段パスが
平坦化後の木を再解決すると、同名の外側ローカルへの後続の読みが接合された宣言へ
束縛されてしまう。

最小再現（チャンク形）:

```lua
local x = 1
if 2 > 0 then local x = 5 end
output.setNumber(1, x)   -- 原文 1、最適化全構成 5
```

同型: 関数内形（1→5）、`else` 側形、ループ内形（2→10）、`local function` のみの
本体（nil のはずが関数が漏れる）、`repeat` 本体形——`repeat` では接合された宣言が
`until` 条件から合法的に見えるようになり反復回数まで変わる（1→2）。

帰属: `constant-folding` 単独無効化で全構成一致に復旧（diffexec トグル）。
第223ラウンド以前から存在する接合経路の欠陥で、同ラウンドの `return` 対処と
同型の「ブロック境界が意味を持つ文を接合してしまう」問題である。

## 修正

`crates/storm-lua-minify/src/passes/literal_folding.rs` のみ:

1. `selected_body`: トップレベル `return` に加え、トップレベルで
   `Local`／`Localfunc` を宣言する本体も `Node::Do` で包む。
2. 平坦化（`simplify_node_inner` の Block 処理）: トップレベルでローカルを宣言する
   子ブロックは位置によらず `do` で包む（末尾位置でも、`repeat` 本体の `until`
   可視性のように文リストの外側に文脈があるため、`return` の末尾例外は適用しない）。
   `return` については従来どおり非末尾位置のみ包む。

回帰テスト 1 件（`constant_selected_body_with_local_stays_scoped`）を、
実際のパイプライン合成（`fold_expressions` → `simplify_control_flow`）
経由で追加した。**修正前コードでは落ち、修正後では通る**ことを両方確認済み
（第223ラウンドの回帰テストが別入口を通っていて弱かった教訓への対処）。

## 検証

- ワークスペーステスト: 最終基点 `d0ccc82`（第230ラウンド先端）へ rebase した
  ブランチで **50 スイート／1,597 件合格・0 失敗**（RC=0、新規回帰テストの合格を
  含む）。分岐元 `c9bffcc` 時点の測定では 1,582 件全合格。
- diffexec: 分岐元 `c9bffcc` 基準で a07／a08（v18）、m01／m02（変異）、プローブ
  2 件（Localfunc 漏れ／repeat-until）が全5構成一致に回復。最終基点 `d0ccc82`
  でも再確認した: base 側メインドライバ 411 件のフラグは 16 件（本修正の対象
  a07／a08、記録対象の別件 d 系 8 件・e 系 2 件、環境 base-fail 2 件、Tolerant
  リテラル近似 2 件）で、第53サイクル残件の self 4 件（k1／a1／a7／a10）は
  第230ラウンドの修正で消滅し、MR ヘッダ 5 件も第225ラウンドで解消済みのまま
  だった。fix 側は v18 残 11 件・変異残 7 件で、回復関係は基点によらず不変。
- Tier FULL（コーパス 4,155 ファイル／16,620 行）: base 側 TSV の sha256 は
  `62cea510687a4c29da5d760a238bea47f6c35ec5138f35bab2e37a3accf4f961` で、
  分岐元 `c9bffcc` から最終基点 `d0ccc82` までの 5 先端
  （`c9bffcc`／`6ef03eb`／`b06a639`／`1b0b7ca`／`d0ccc82`）全てでバイト一致を
  実測した（第227〜230ラウンドはいずれもコーパス出力不変）。head 側は最終基点
  でも sha256 `743431aa4bb3142c3661c78dfdbf63219052704c8d763fbd35cda85d73279be7`
  で、base からの変更はコーパス **1 ファイルのみ**（source sha
  `ccf047aff73a92f8fb8f77a519112db081151629fca6061ceeda2eea7ea90d6b`）。
  default 出力は 5,137→5,144 バイト（+7 = ローカル宣言本体を `do` で包む分）。
  当該ファイルは diffexec の全5構成で修正前・修正後とも同一トレース
  （`vm-error`、トレース sha 一致）であり、**振る舞いは不変**、変化は本修正の
  意図した出力変化のみであることを確認した。
