# 定数畳み込みが return を含む if 本体を接合し、パース不能コードを生成した（2026-10-31、未公開）

## バグ

w6 第53サイクル（第212〜220ラウンド変更面の新規狩り＋signed_factoring／融合近傍の変異狩り）で発見。融合の対照変異（return を2つ持つ1回使いヘルパー、c53-mutants-v17/m19）が既定構成で vm-error になり、ddmin で `constant-folding` の単独無効化により復旧することを特定した。最小再現:

```lua
local function f(a)
  if 2 > 0 then return a end
  return 99
end
```

生成コードは関数本体に `return a` の直後へ `return 99` を同一ブロックで接合した形になり、Lua の文法（return はブロックの最終文でのみ許される）に反して読込時に拒否された。plain は正常、opt／safe／target32／target128 の全てが vm-error。条件が定数偽の場合・引数が非定数の場合は発現しない。定数真の条件分岐の本体が return で終わり、後続文が存在するあらゆる関数で発現しうる（本体の間にローカル宣言がある形、else 側が選択される形でも再現を確認）。

## 原因箇所

`crates/storm-lua-minify/src/passes/literal_folding.rs` の `simplify_node_inner`。定数真と確定した if を、その本体ブロックそのもの（`Node::Block`）へ置換していた。親ブロックの平坦化処理は文位置にある素の `Block` を親へ接合するため、本体内の `return` が親ブロックの途中へ入り込み、後続文が return の後ろに並んだ。同ファイルの exact-safe 経路（`fold_exact_safe_node_inner`）は同じ置換で本体を `Node::Do` に包んでおり無事だった——2つの経路で扱いが食い違っていた。

## 修正

- 定数選択された本体（if 本体・else 本体の両置換箇所）を、トップレベルに `return` を含む場合は `Node::Do` で包む（`selected_body` ヘルパー）。含まない場合は従来どおり平坦に接合し、サイズへの影響を最小化した。
- ブロック平坦化の堅牢化: トップレベル `return` を含む子ブロックは、親の末尾位置にある場合を除き接合せず `do` で包む。他の生成源から同型のブロックが現れても壊れないようにした。
- 回帰テスト2件を追加: 定数選択された return 持ち本体の出力が再パース可能であること（修正前コードで失敗を確認済み）／return を持たない本体は従来どおり `do` なしで平坦化されること。
