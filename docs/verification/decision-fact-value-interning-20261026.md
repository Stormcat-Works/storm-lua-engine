# 決定理由の fact 値共有（2026-10-26、未公開）

`OptimizationReason::decision` が理由ごとに新しく確保していた
fact 値の `Arc<str>` を、内容が等しい値同士で共有するよう変更した。
生成 Lua・候補選択・schema1 のマップ本体・`x_storm` の説明履歴は
維持する。Map 比 1.2 の目標は未達のままであり、この変更はその
達成を主張しない。

## 原因

決定理由の fact 値は、ノードごとの観測値ではあるが、その多くは
短い構造化文字列（演算子・リテラル種別タグ・式サイズ・許容誤差
ビット）であり、畳み込みノードをまたいで繰り返し現れる。従来は
理由ごとに fact 値を `String` から `Arc<str>` へ変換してコピーして
おり、合成入力 dense-normal の定数畳み込みでは、畳み込みノード
480 個に対して fact 値だけで約 4,800 回の余分な確保が発生していた。
前回の綴り共有では、fact 値はノードごとに異なりうるため共有して
いなかった。

## 変更

`crates/storm-lua-syntax/src/explanation.rs` の `decision` のみ
変更した。公開 API のシグネチャは変えていない。

- code・basis・fact key の綴りキャッシュと fact 値のキャッシュを
  1 つの `OnceLock`＋`Mutex` にまとめ、1 回の `decision` 呼び出し
  ではロックを 1 回だけ取得する。
- fact 値は内容で引き、初出の値だけを確保し、以後は同じ内容の
  `Arc<str>` を複製して返す。直列化される説明は従来とまったく
  同一であり、`Arc<str>` の等価性・ハッシュは内容で決まるため、
  理由の比較や検証にも影響しない。
- fact 値のキャッシュには上限（4,096 件）を設けた。fact 値は
  ノードごとに異なりうるため、上限なしではキャッシュが入力内容に
  比例して増え続ける。上限に達した後の値は従来どおり新しい
  `Arc<str>` へ変換するため、メモリ保持は上限に bounded され、
  巨大な入力でも共有の有無が出力に影響しない。

## 測定

合成入力 dense-normal（46,022 バイト）で、VM 2 コア、各条件 31 反復
の中央値。アロケーション計数はハーネス側の計数アロケータによる。
測定時の load average は 0.3〜2.3 程度。

| 測定 | 変更前 | 変更後 |
| --- | --- | ---: |
| `fold_expressions`（追跡あり）の確保回数 | 49,491 回 | 44,691 回 |
| `fold_expressions`（追跡あり）の確保バイト数 | 2,802,102 B | 2,679,222 B |
| `fold_expressions`（追跡なし）の確保回数 | 29,091 回 | 29,091 回 |
| `fold_expressions`（追跡あり）の時間 | 約 5.17ms | 約 5.01〜5.05ms |
| `fold_expressions`（追跡なし）の時間 | 約 2.67ms | 約 2.43〜2.47ms |
| `fold_expressions`（追跡あり−なしの差） | 約 2.50ms | 約 2.58〜2.59ms |

確保回数の減少 4,800 回は、畳み込みノード 480 個あたり 10 回と
ちょうど一致する。追跡なし側の確保回数が変わらないことから、
削減が追跡経路だけのものであることも確認できる。時間については、
追跡あり・なしの両方が同程度に変動し、差は測定ノイズの範囲内
（約 2.5〜2.6ms）にとどまるため、この変更単独の時間改善は主張
しない。確保回数で約 9.7%、確保バイト数で約 4.4% の削減が確実な
効果であり、候補ごとに畳み込みが走る既定 compile では回数分だけ
積み上がる。

## 検証

- 生成コードは変更前後で同一（SHA-256 一致、10,921 バイト）。
- 公開 API のマップは、mappings・names・sources・sourcesContent・
  version・`x_storm` の reasons を含め全項目が同一である。差が出た
  のは `x_storm.producer.dirty`（未コミット時は true が正しい）と
  それを覆う `x_storm.integrity` のダイジェストのみで、変更を
  コミットすれば消える種類の差である。
- 対象テスト（syntax・minify・build）と全ワークスペースのテスト、
  `cargo xtask check`・fmt・clippy を通過した。
