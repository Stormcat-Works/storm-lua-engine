# final-dead-store-elimination の return 前ストア欠落（2026-10-30、ワーカー w9）

## 症状

最適化後コードで、分岐内の早期 return の直前に置かれたグローバルへの
代入が消え、後続のコールバック呼出や次ティックで古い値が読まれた。
差分実行では、plain と最適化後で描画テキストが異なり、plain が後続
ティックで書いていた output 書込みが最適化後では一度も書かれなかった。

## 機構

`passes/final_stores.rs` は後方生存解析である。関数本体の終端では
非固定グローバルと関数間捕捉束縛が生存集合に入るが、ネストした
If／Do ブロックはフォールスルー後の生存集合を `live_out` として
掃引される。`return` は従来、自身の効果（返却式の読み）の転送しか
されず、フォールスルー生存集合のまま処理された。そのため、分岐体内
の `代入；return` において、フォールスルー経路上の後の上書きで当該
束縛が殺されていると、代入が dead と判定されて除去された。しかし
return 経路は関数を抜けるため、そこで残るべき値は関数終了時点で
生存している（非固定グローバルはコールバック終了時も生存）。
単独パス無効化スイープ（正本 73 件）では
`final-dead-store-elimination` の無効化でのみ plain と一致した。

## 修正

`clean_block` へ関数終了時生存集合（`persistent_globals`：非固定
グローバル＋関数間捕捉束縛）を `exit_live` として通し、`return` に
遭遇したら生存集合を `exit_live`＋返却式の読みへリセットする。
これにより、return より前の文は関数終了時生存で判定される。
ループ本体は従来通り掃引対象外で、goto 等の非構造フローがある
場合は従来通りパス全体が不適用である。

## 回帰テスト

`passes/final_stores.rs` に 3 件追加：

- 分岐内の return 前グローバルストアを保持すること。
- Do ブロック内の return 前グローバルストアを保持すること。
- return 前の死んだローカルストアは従来通り除去されること。
