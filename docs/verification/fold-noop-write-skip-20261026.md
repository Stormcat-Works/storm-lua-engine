# 定数畳み込みの無変更書き戻し省略（2026-10-26、未公開）

定数畳み込み（`constant-folding`）の2走査で、値が変わらないのに
`IndexMut` で由来スロットを空にしてから復元していた書き戻しを3か所
省略した。生成 Lua・候補選択・schema1 のマップ本体・`x_storm` の
説明履歴は維持する。Map 比 1.2 の目標は未達のままであり、この変更は
その達成を主張しない。

## 原因

`NodeArena` の `IndexMut` は書き込み前に由来スロットを空にする。
`finish_rewrite` は値が変わっていない場合は共有スロットを復元する
ため最終結果は同じだが、書き戻し自体がスロットの無効化と復元、
および `Arc::make_mut` の分岐を毎回発生させる。定数畳み込みは全
ノードを2走査するため、無変更の書き戻しが以下の3か所に集中して
いた。

- 数値描画：`render_num` は既に正準形のリテラルに対して入力を
  借りて返すが、従来は `into_owned` で複製してから必ず代入して
  いた。合成入力では 1,600 個の数値ノードの多くが該当する。
- 制御フロー単純化の `If`：アームを落とさなかった場合でも、再
  構成した `If` ノードを必ず代入していた。
- 制御フロー単純化の `Block`：子ブロックの平坦化や空 `do` の除去
  が無かった場合でも、再構成した `Block` ノードを必ず代入して
  いた。

## 変更

`crates/storm-lua-minify/src/passes/literal_folding.rs` のみ変更した。

- 数値描画は、描画結果の文字列が現在のリテラルと等しい場合は代入
  を省略する。文字列が等しければ値は同一であり、`finish_rewrite`
  はどちらの経路でも共有スロットを復元するため、由来の最終状態は
  変わらない。描画が変わる場合は従来どおり代入し、書き換え理由を
  記録する。
- `If` の単純化は、アーム数が変わっていない場合は代入を省略する。
  アームは変更されず順序どおりに保持されるため、アーム数が等しい
  ことはアーム列が等しいことと同値である。アームを落とした場合
  は従来どおり代入する。
- `Block` の単純化は、出力文列が入力文列と等しい場合は代入を
  省略する。平坦化や除去があった場合は従来どおり代入する。

いずれも、値が実際に変わる場合の由来処理（書き換え理由・
dispositions・トークン／名前の保持判定）は従来のままである。

## 測定

合成入力 dense-normal（46,022 バイト）で、VM 2 コア、各条件 31 反復
の中央値。変更前後を交互に測定した（stash による前後比較）。

| 測定 | 変更前 | 変更後 |
| --- | ---: | ---: |
| `fold_expressions`（追跡あり−なしの差） | 約 2.61ms | 約 2.59〜2.73ms（変化なし） |
| `simplify_control_flow`（追跡あり−なしの差） | 約 0.85ms | 約 0.64ms |
| `constant_fold` 全体（追跡あり−なしの差） | 約 2.71ms | 約 2.47ms |
| 既定 compile（Map あり−なしの差、11 反復） | 約 58.2ms | 約 60.8ms（測定ノイズの範囲内） |

数値描画の省略はパス単体の追跡差には現れなかった（無変更経路の
復元自体が安価なため）が、重複文字列の確保は消える。改善の主体は
制御フロー単純化の `If`／`Block` の省略である。既定 compile の差は
全パス無効時の差だけでも測定ごとに約 2ms 変動するため、この変更
単独の寄与としてはパス単体の値を主に見る。変更ノード数は変更前後
とも 480 個、生成コード長は 10,921 バイトで同一である。

残りの `fold_expressions` の追跡差（約 2.6ms）の大半は、実際に畳み
込まれたノードの由来処理（書き換え理由の生成と説明の記録）であり、
これは生成物の `x_storm` 説明履歴そのものであるため、安易な省略の
対象にはしない。次回の候補として残す。

## 検証

- 生成コードは変更前後で同一（SHA-256 一致）。
- 公開 API のマップは、mappings・names・sources・sourcesContent・
  version が変更前後で同一である。
- `x_storm` は、reasons・dispositions・origins・mappings・contexts・
  relations・constructs・generated・sources を含め、producer と
  integrity を除くすべての項目が変更前後で同一である。producer と
  integrity の差異は、未コミット時の `producer.dirty` とそれを覆う
  ダイジェストによる正しい変化である。
- 対象テスト（syntax・minify・build）と全ワークスペースのテスト、
  `cargo xtask check`・fmt・clippy を通過した。
