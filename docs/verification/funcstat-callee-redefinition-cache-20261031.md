# 関数定義による被呼出側の再定義が利用可能式のキャッシュを失効させない（2026-10-31、未公開）

## バグ

w6 第50サイクルの境界スイート v15 で発見（v15-fs-betweendefs）。同じ束縛への関数定義を挟んで既知関数を 2 回評価する形状で、2 回目の呼出結果が 1 回目の呼出のキャリアへ書き換えられ、再定義後の関数の結果が失われた。再現: `function h() return 1 end` の後に `local a = h()`、続けて `function h() return 2 end` の後に `h()` を再評価すると、原典 12（a*10 + 2）に対し opt / safe / target は 11（a*10 + a）を出力した。代入による再定義（`h = function() return 2 end`）でも同じく発現した（v15-fs-assignredef）。

## 原因箇所

2 箇所の欠落の組合せであり、片方だけでは Funcstat 形は直らない（中間状態で検証済み: 消費側の修正のみでは代入形だけが復旧し、Funcstat 形は残る）。

1. `crates/storm-lua-analysis/src/effects.rs` の `statement_into` に `Node::Funcstat` と `Node::Localfunc` の腕が無く、関数定義文は効果を何も生まなかった。そのため束縛ごとの書込みを追う消費者は、関数定義による再定義を書込みとして観測できなかった。
2. `crates/storm-lua-minify/src/passes/available_expressions.rs` の `add_candidate` は、候補式の依存集合として効果解析の `reads` をそのまま使っていた。既知関数の呼出では、効果要約が被呼出側自身の読み／書込みで呼出の効果を置き換える規約のため、被呼出側の束縛は呼出の `reads` に現れない。そのため被呼出側が再定義されても（代入形では書込み自体は記録されていたにもかかわらず）キャッシュ項目が失効しなかった。

## 修正

1. effects: 名前対象の Funcstat を対象束縛への書込みとして記録し、添字対象は Assign の lvalue 規約（対象式の読みと呼出のみをマージし、throw しうる）に合わせた。Localfunc は解決器が文ノード自体に記録する自束縛への書込みとして記録した。関数本体は定義時には実行されないため、その効果はマージしない。回帰テスト2件を追加。
2. available_expressions: 候補の依存集合へ、式中の呼出が名前経由でディスパッチする束縛（被呼出側束縛）を加えるヘルパー `collect_callee_bindings` を追加した。入れ子関数本体には入らない（その呼出は式の評価時には実行されない）。回帰テスト3件を追加（Funcstat 再定義、代入再定義、被呼出側が無変更の対照）。

全5件の回帰テストは修正前のコードで失敗すること（対照1件は修正前後とも通過）を確認済み。
