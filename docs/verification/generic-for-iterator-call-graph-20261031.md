# ジェネリック for の暗黙イテレータ呼出が呼出グラフに欠落し、スクラッチスロットが衝突する（2026-10-31、未公開）

## バグ

w6 第47サイクルの境界スイート v14 で発見（候補 C）。外側ローカルを捕捉するジェネリック for のイテレータ・クロージャがグローバルを書き、囲み関数の後方でローカルが宣言される形状で、opt / safe が後置ローカルをグローバルへ降格し、クロージャ内のグローバル書込みと同一の発行名を割り当てるため、イテレータの書込みがアキュムレータを破壊した（原典 2 に対し最適化後 4）。

第48サイクルの切り分けで、十分な無効化集合が {function-local-globalization} / {temporary-global-packing} / {scope-renaming, api-alias-optimization} の複数ある相互作用形であること、再現集合が p-mx-v1 / v2 / v2c（opt / safe で乖離）であることを確定した。p-mx-v3 はループ本体のメンバ読み巻き上げによる乖離（Codex 指摘 6 の MR ヘッダ形）であり、本件とは機構が異なる。while 形（条件に明示 Call がある）では発現しない。

## 原因箇所

`crates/storm-lua-minify/src/passes/temporary_globals.rs` の `scan_owner` と `crates/storm-lua-minify/src/passes/function_globalization.rs` の `scan_graph`。両パスはスロット割当ての干渉判定を自前の呼出グラフ（Call ノードからのみ構築）に依存するが、ジェネリック for（`Node::Forin`）がイテレータ値を各ステップで暗黙に呼ぶことは Call ノードとして現れないため、呼出側とイテレータ側の所有者が「干渉しない」と判定されていた。

- temporary-global-packing: 呼出側で生存する `__fs` スクラッチ（FLG が変換したアキュムレータ）と、イテレータ側に閉じ込められた未読グローバル G が同一色に割り当てられ、両方とも `__gs0` へ書き換えられて統合された。
- function-local-globalization 単独でも同根: イテレータ自身の対象ローカルと、ループを跨いで生存する呼出側ローカルが同一の `__fs` スロットを共有し得た（第49サイクルの隣接探査 x-iter-own-local で実証）。

効果解析（storm-lua-analysis の effects）では Codex 指摘 6 の修正で Forin の暗黙呼出がモデル化済みだが、この 2 パスの自前スキャンには同じ配慮が無かった。

## 修正

両スキャンに、Call ノードと同一の規約で Forin のイテレータ呼出を記録する処理を追加した（呼出対象の解決ロジックはヘルパーへ抽出して Call 側と共有）。

1. イテレータ式が名前で、チャンク定義関数へ解決できる場合は呼出辺を張る（FLG 側は再代入された束縛を呼出対象とみなさない既存の書込み回数ガードをそのまま適用）。
2. ビルトイン参照へ解決できる場合は既存どおり既知として扱う。
3. イテレータ式が Call の結果である場合は、その呼出自体は歩行で記録されるものの、結果の関数値の呼出は未知として扱う（チャンク関数が返すクロージャは呼出グラフでは到達できないため）。ただし pairs 等、結果が標準イテレータであるビルトイン呼出は既知として扱い、従来の詰め込み・グローバル化を妨げない。
4. それ以外（引数・未解決名・メンバ値など）は未知呼出として扱う。

回帰テスト 6 件を追加（TGP: イテレータ所有者との干渉、Call 結果イテレータの未知扱い、ビルトインイテレータでの詰め込み維持、FLG→TGP の相互作用そのもの。FLG: イテレータ／呼出側のスロット分離、ビルトインイテレータでのグローバル化維持）。ビルトイン維持の 2 件を除き、修正前のコードでは失敗することを確認済み（ビルトイン維持の 2 件は修正前後とも通過）。
