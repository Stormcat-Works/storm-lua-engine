# immutable キャリア合成のクローン由来共有による追跡コスト削減（2026-10-26、未公開）

immutable キャリア合成（`immutable-carrier-synthesis`）で、繰り返し式の
複製に対する由来付けを共有するよう変更した。生成 Lua・候補選択・
schema1 のマップ本体は維持する。Map 比 1.2 の目標は未達のままであり、
この変更はその達成を主張しない。

## 原因

`NodeArena::derive_from` の高速経路は、対象ノードの値全体が源ノードと
等しい場合にのみ由来スロットを共有する。`clone_subtree` は子を先に複製
してから親を積むため、子 ID がずれた内部ノードでは値の等価性が崩れ、
低速の書き換え経路（理由の生成・トークン／名前の保持判定・新規スロット
確保）が走っていた。これは API 別名パス・単一使用ローカルのシンク・
captured 単一使用ホイストで `derive_from_clone` が解消したのと同じ構造
である。なお、common-offset 吸収の `clone_subtree` は複製される項が大半
リーフであり高速経路に既に載るうえ吸収回数に上限があるため、測定可能な
効果が見込みにくく、今回は対象としなかった。

## 変更

- `crates/storm-lua-minify/src/passes/immutable_synthesis.rs` のみ変更し、
  `clone_subtree` の `derive_from` を `derive_from_clone` に置き換えた。
  複製される式は純粋な複製であり、種類と識別子・リテラルの位置は源と
  同じで子 ID だけが異なるため、`derive_from_clone` の保証に合致する。
  種類が異なる場合や source snapshot を共有しない場合は従来の
  `derive_from` へ委譲する。
- 複製された式はキャリアの初期化子になる。出現箇所のキャリア名への
  書き換えと定義関係の記録は従来どおりであり、共有した源スロットが
  壊れることはない（関係の記録はスロットをコピーしてから行う）。
- 新規合成ノードを作る箇所や、書き換えそのものを表す箇所は従来のまま
  である。

## 測定

合成入力（単一書き込みの数値グローバル 4 個と、深い式
`a*2+b*3+c*4+d*5` を 100 個の関数内で繰り返す 5,526 バイト。候補試行は
693 件＝7 グループ × 出現回数 2..=100 の 99 通りで、1 通りあたりの
複製内部ノードは 7 グループ合計で 18 件）。VM 2 コア。
計数アロケータ付きハーネスで各条件 31 反復の中央値を測った。

| 測定 | 変更前 | 変更後 |
| --- | ---: | ---: |
| パス単体・追跡なし確保回数 | 967,405 回 | 967,405 回（不変） |
| パス単体・追跡あり確保回数 | 1,984,036 回 | 1,965,226 回 |
| パス単体・追跡あり確保バイト数 | 492,524,358 B | 491,597,025 B |
| パス単体・追跡差（確保回数） | 1,016,631 回 | 997,821 回 |
| パス単体・追跡差（確保バイト数） | 73,522,488 B | 72,595,155 B |

追跡なし側が変更前後で完全に同一であることから、削減が追跡経路だけの
ものであることを確認した。削減 18,810 回は、候補試行 693 件のうち
低速由来が走る内部ノード（7 グループ合計 18 件 × 99 通り＝約 1,782 件）
に由来し、1 件あたり約 10.6 回の確保と整合する。時間については、同じハーネスの追跡差が約 153ms から
約 156ms と変動の範囲内であり、時間改善としては主張しない。確保回数の
削減が確実な効果である。

## 同一性

- パス単体の印字：上記合成入力について、stash による前後比較で印字全体
  の SHA-256 が一致し、合成件数も変更前後とも 1 件、候補試行数も
  693 件で同一である。
- 公開コンパイル全体：`onTick` 内で同じ深い式を 12 回繰り返す合成入力で
  stash 前後比較を行い、生成コードは SHA-256 一致（143 バイト）、
  勝者は変更前後とも `optimized:function-global/none`、マップの
  mappings・names・sources・sourcesContent・version は同一である。
  `x_storm` の差は `producer.dirty`（測定時の未コミット状態を示す）と
  それを覆う `integrity` のみで、この入力の説明履歴そのものに差は
  出ていない。なお、この入力の最終出力は別パス（ループ合成）の勝者が
  選ばれるため、immutable キャリア合成の効果はパス単体で確認している。
- 実データの標準検証（コーパス全件比較）は、コミット後に別途実施し、
  作業記録に残す。
