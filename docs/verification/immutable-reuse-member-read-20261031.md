## 問題

`immutable-global-expression-reuse`（pass id 18）は、先行ローカルに
束縛された式と一致するメンバ読みを、関数本体内でもローカルへの
参照に置換する。置換の可否は束縛レベルの effects（基底束縛が
再束縛されないこと）だけで判定していたため、基底オブジェクトへの
メンバ書込み（`t.x = 99`）が見えず、関数定義後に書込み・呼出し前に
評価されるはずの読みが、定義時点の古い値に化けていた。

最小再現（第57サイクルで切り分け、本サイクルで先端再確認）:

```lua
local t = {x=3}
local a = t.x
local f = function() return t.x end
t.x = 99
output.setNumber(1, a + f())   -- 原文 102 → 生成 6（Smallest/Safe 共通）
```

根因: `storm_lua_analysis::effects` の `expr_into` は `Node::Index`
について基底束縛の読みだけを記録し `stable=true` を維持する。pass の
`dependencies_are_single_write` は束縛の再書込みだけを数えるため、
「基底が再束縛されない」ことと「基底経由の読み値が変わらない」こと
が混同されていた。置換先が関数本体（任意の後時点で実行されうる）
である点が、この混同を顕在化させた。

## 修正

`MemberReadGuard` を pass 内に追加し、キャリア式が `Index` ノードを
含む場合に限り、式内の全メンバ読みについて基底束縛の時間不変性を
要求する（含まれないキャリアは従来どおり無条件で通す）:

- 基底が Global の場合: `resolver::api_roots` の名前であり、かつ
  `effects::mutated_builtin_roots`（エイリアス経由のメンバ書込みと
  escape を含む既存解析）に現れないこと。
- 基底が Local の場合: 閉じたテーブルであること。再束縛なし、かつ
  チャンク全体の文脈走査（`scan_member_uses`）で (1) メンバ書込みの
  基底として現れない（別名経由・関数内書込み・メソッド定義を含む）、
  (2) 値として使われない（エイリアス・escape なし）、(3) 宣言が
  テーブルコンストラクタ初期化である、の全てを満たすこと。
- それ以外の基底（引数・関数束縛・名前で終わらないチェーン等）は
  証明不能として再利用しない。

文脈走査は代入ターゲット／メソッド基底／通常の値位置を区別する
（tables.rs の `scan_immutable_table_uses` と同じ規律）。回帰テスト
8 件: メンバ書込み跨ぎ（再現形）／閉じたテーブルでの再利用維持
（正例）／escape／関数内書込み／別名書込み／コンストラクタでない
ローカル／変更される組み込みルート（`math.pi` 書込み）／メソッド
定義。pass 単体テストは 13 件全合格（従来 5 件＋新規 8 件）。

## 副次項目: lifeboat の `\n` のみの行計算（CR のみの入力での到達可能性）

結論: **lifeboat 2 ファイル内の当該式だけでは直らない**ため、本
サイクルではコード変更を行わず、根因を特定して親へ判断事項として
残す。調査結果:

- `lifeboat.rs` / `lifeboat_ambient.rs` の `line`（`\n` 数 + 1）と
  `count`（`str::lines().count()`）は到達可能なコードだが、その値で
  作られた `LinkedRange` は `link_lifeboat` の出口で
  `link::exclude_blanked_ranges` により**バイトオフセットから全面
  再計算**され、行フィールドは破棄される。実際にこの 2 式を lexer
  意味論へ差し替えても、CR のみモジュールの range は変わらない
  ことを回帰テストで確認した（差替は検証後に差し戻し済み）。
- 再計算に使われる `storm_lua_syntax::source_position::LineIndex` は
  LF／CRLF 前提（ドキュメント明記）で、単独 `\r` を行開始として
  数えない。一方 lexer は `\r` を改行として数える
  （`lexer.rs` の改行処理、第222ラウンドで link.rs が lexer 側へ
  統一した意味論）。したがって CR のみ行末を含むモジュールでは、
  lifeboat の最終 range（および LineIndex を使う全ソースマップ／
  診断）は lexer の行番号とずれる。これは到達可能である。
- ただし LineIndex は storm-lua-syntax の共有契約（診断・全ソース
  マップが依存）であり、その改行意味論の変更は lifeboat 局所修正の
  範囲を超える横断的な判断（マップの行意味論を lexer に合わせるか
  どうか）を伴う。本サイクルの副次項目の範囲外として、判断事項に
  残す。

## 備考（検証中の異常 2 件、いずれも結論に影響なし）

- 初回の修正後 diffexec で再現が残って見えたのは、コンパクション
  中断を跨いだ bench ビルドが**修正前ソースからビルドされた古い
  バイナリ**だったため。バイナリの mtime（20:28）とソース mtime の
  比較および計測版での切り分けで特定し、再ビルド後は全構成 102 を
  確認した。

  （`compile_is_deterministic_across_parallel_repetitions`）は現行
  ツリーに存在しないテスト名であり、共有 target 内の古いテスト
  バイナリの混入と判断した。差し戻し後の同クレート再実行は
  139 件全合格で再現しない。
