# 関数インライン融合にローカル予算チェックが無く、読込不能コードを生成した（2026-10-31、未公開）

## バグ

w6 第52サイクル（Codex 指摘 #7 系「ローカル挿入パスに予算チェックなし」クラスの完結監査）で発見。関数インライン化（`one-use-function-fusion`）は、被呼出関数のパラメータ宣言と本体を呼出側へ継ぎ足す際、継ぎ足し後の同時有効ローカルのピークを確認していなかった。2 つの現れ方を確認した:

1. 潜伏形（c52-probes/e12-fus4-ontick-195）: 呼出側の最大値 195＋被呼出側のピーク（引数 3＋本体ローカル 3）で 201 になり、グローバル化系パスを無効化した構成で vm-error。既定構成では後段のグローバル化が継ぎ足されたローカルを救済する。
2. 既定構成の形（c52-probes/c17-screenloop-fn-197）: 周期描画シーケンスを抽出した 1 回だけ使われるヘルパー関数（ループ本体を含む）が、引数 197 の呼出側へ融合され、ヘルパー側のピーク（引数＋別名ローカル＋for 制御値）が加わって 200 を超え、opt／target32／target128 が vm-error になった。画面ループ合成自体の予算ゲートは呼出側の元の形状では正しく働くが、融合後の合成ピークは誰も見積もっていなかった。

## 原因箇所

`crates/storm-lua-minify/src/passes/inline_functions.rs` の融合箇所。同クラスの 11 例目。これで、静的列挙した未会計の挿入パスは全て処置済みとなった（残る api ローカル化の別名挿入は Codex 指摘 #7 の既知残件として w4 に割当済み）。

## 修正

- 融合箇所が確定した後、継ぎ足し前に判定する: 呼出側のそのブロックにおける最大値＋被呼出側のピーク（いずれも共有ヘルパー `max_active_locals` による関数全体の最大値）が `MAX_LOCALS`（200）を超える場合は融合をスキップする。末尾形の結果ローカルは呼出文自身の宣言であり、呼出側の最大値に既に含まれているため二重に数えない。
- 回帰テスト 2 件を追加: 予算超過でスキップ／上限内で発火。
