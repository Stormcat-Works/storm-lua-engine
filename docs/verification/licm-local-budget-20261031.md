# ループ不変式ホイスティングにローカル予算チェックが無く、200 上限の関数が読込不能コードを生成した（2026-10-31、未公開）

## バグ

w6 第51サイクルの境界スイート v16（第208ラウンドの予算チェックに対する隣接形状の確認）で発見。対象モードのループ不変式ホイスティング（LICM、`joint-api-local-licm` レイアウト）が、巻き上げ先の関数について同時に有効なローカル数の上限を一切確認せず、グループごとに preheader へローカルを 1 つ挿入していた。同時有効ローカルがちょうど 200 の関数（引数 195 + ローカル 1 + 数値 for の 4 枠）にループ内の純粋ホスト読み（`input.getNumber(1)`）があると、挿入で 201 になり、生成コードが VM に読込を拒否された。再現（c51-probes/pc-licm-hostread-200）: plain / opt / safe は全て正常終了しトレース一致、target32 / target128 のみ vm-error。引数 194（199 有効）の対照では巻き上げが発火し全構成一致した。

## 原因箇所

`crates/storm-lua-minify/src/passes/loop_invariant.rs`。第208ラウンドで S1（single_member_cache）／MR（loop_member_reads）／SMC（straightline_member_reads）の 3 パスへ入った `max_active_locals` + `MAX_LOCALS` の予算チェックが、同じく対象モードでローカルを挿入する LICM には入っていなかった。静的監査でも、同ファイルがこの共有ヘルパーを参照していないことを確認した（参照しているのは上記 3 パスのみ）。Codex 検出 #7・w6 候補 B と同種の欠落の 4 例目。

## 修正

`loop_invariant.rs` の Transformer に、囲み関数ごとの予算管理を追加した。

- `body_stack` の要素を関数本体に引数数を添えた `(NodeId, usize)` とし、チャンク直下のループは暗黙の最外文脈（ルートブロック、引数 0）として扱う。
- 関数ごとに `max_active_locals`（共有ヘルパー、その時点の入力ツリーで算出）をメモ化し、本パスがその関数へ挿入したローカル数を数える。グループのローカルを作る直前に `fn_max + inserted + 1 > MAX_LOCALS` ならそのグループをスキップする（出現箇所は主張せず元の位置に残すため、内側ループが同じ関数で再試行しても同じ判定になる）。会計方法は第208ラウンドの 3 パスと同じ保守的な関数全体最大値方式。
- 回帰テスト4件を追加: 関数が上限ちょうどでスキップ／上限−1 で発火／チャンクが上限ちょうどでスキップ／2 グループ目が 1 グループ目の挿入で埋まった予算に当たってスキップ（累積会計）。

上限系の回帰テスト3件は修正前のコードで失敗し、発火対照1件は修正前後とも通過することを確認済み。

## 検証

- ワークスペーステスト全通過（1,526 件 = 第211ラウンド時点 1,522 + 新規 4）。fmt 通過、clippy は本変更への新規警告なし（lib の既存エラー・警告は single_member_cache.rs / literal_folding.rs の未変更箇所のみ）。
- 再現 pc-licm-hostread-200 は全5構成で一致に転じ、199 の対照では巻き上げが維持されることを生成コードで確認した。base / head の diffexec は同ケースで機能的に同定済み（base は target のみ vm-error、head は全構成 ok）。
- 境界スイート v16＋変異＋全回帰スイートのドライバ（242 件、sweep 968 行 / diffexec 1,210 行）を修正前後で実行し、フラグ集合とトレースハッシュが完全一致（残る 9 件は全て既知クラス: MR ヘッダ 7 件は w4 第95サイクル対応中、環境非バグ 1 件、既存分類 1 件）。
- Tier FULL（base `8bb33bbc3` = FULL-VERIFY-TIP → head、実世界コーパス 4,155 件 × 4 条件 = 16,620 行、開発ホスト1）: base / head の corpuscheck TSV がバイト単位で完全一致（SHA-256 `e88ee2b4…`、両側とも ok 4,128 / error 27 × 4 条件）。LICM は対象モード専用であり、本修正は上限近傍での発火抑制のみのため、無対象コーパスへの影響ゼロは設計どおり。回帰 0 件。
