# Codex 第3回指摘7・14・15（連結モジュールの捕捉／終端ラベル／ローカル予算）の修正 — 検証記録

対象: `crates/storm-lua-build/src/link.rs`（静的リンクの展開機構）
担当: w9 第61サイクル

## 共有する根

3件とも、モジュール本体を require 位置へテキストで継ぐ「inline 展開」の
設計に起因する。本体が import 側チャンクの字句スコープの中で生きること、
本体の直後に glue（結果代入）が付くこと、結果変数を巻き上げローカルに
することが、それぞれの欠陥を生んでいた。

## 指摘7（High）: import 側ローカルの捕捉

モジュールの自由名は本来グローバル環境へ解決されるべきところ、inline
展開では import 側で宣言された同名ローカルに字句的に束縛された
（書込み形 r3-07: 期待 1 → 2、読み形 r3-07r: 期待 nil → 1、
クロージャ形 r3-07c: 期待 nil → 1）。

## 指摘14（Medium）: 終端ラベルの無効化

本体末尾のラベルの直後に結果代入が付くことで、そのラベルがブロック
末尾ラベルでなくなり、ラベルへの goto が「ローカルのスコープ内への
跳躍」として素の Lua 5.3 に拒否された（r3-14: ロード不可）。
プロジェクト VM の寛容な goto 書換えはこの欠陥を隠すため、回帰確認は
素のバックエンド Lua での受理と実行結果で担保する。

## 指摘15（Medium）: リンカ生成ローカルの予算超過

結果変数をモジュールごとの巻き上げ `local` にしていたため、200 本の
ローカルを使い切った entry が require するだけで上限超過になった
（r3-15: ロード不可）。

## 修正（展開機構そのものの変更）

- モジュール本体は、連結チャンクの先頭で結果変数へ代入される関数
  として定義する。定義位置では利用者ローカルが一切宣言されていない
  ため、本体の自由名は本来の意味論どおりグローバルへ解決される。
  本体内の return はそのまま関数の return になり、末尾ラベルは関数
  本体の最終文のままになる（指摘7・14）。
- 最初に require された位置では呼び出し glue
  （`V = V()`、nil なら `true` へ正規化）を発行し、2回目以降は結果
  変数の参照のみに置換する。実行順序と一回だけ実行される意味論は
  従来の inline 展開と同一（require はチャンクトップレベルの文に
  限られるため、深さ優先の出現順 = 実行順）。
- 結果変数は予約名グローバルとし、リンカはローカルを一切追加しない
  （指摘15）。名前は従来どおりプロジェクト内の全識別子と衝突しない
  よう生成される。
- チャンクレベルで `...` を使うモジュールは、関数化すると `...` の
  意味が変わるため従来の inline 展開へフォールバックする。ambient
  メンバーも注入位置がチャンク先頭で捕捉が起きないため inline 展開
  を使う。inline 側にも2点の改善を入れた: NoReturn の結果代入を
  do ブロックの外へ移動（指摘14の同型対策）、末尾 return の直前が
  ラベルの場合は IIFE へ落とす（TailReturn 版の指摘14対策）。
- 形状分類（Shape）と末尾 return のテキスト手術はラッパ方式では
  不要になり、inline フォールバック専用になった。

回帰テスト3件（捕捉しないことの構造確認、終端ラベルが本体最終文に
残ること、リンカがローカルを追加しないこと）を link 単体テストへ
追加。旧形状を前提にしていた既存テスト6件と、生成 prefix の位置を
前提にしていた診断／マップ合成テスト2件を新レイアウト相当へ更新した。
