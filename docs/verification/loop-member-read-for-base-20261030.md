# ループ内反復メンバ読取ホイストの for 変数基底への拡張（2026-10-30、未公開）

## 概要

`loop_member_reads`（target モード限定レイアウト `joint-api-local-mr` /
`joint-api-local-licm-mr` の構成変換）は従来、基底が local（書込み 0・
テーブル構築子初期化子）または global（単一代入・テーブル構築子）の場合に
のみ、ループ前のプレヘッダへ `local c = B.K` を出していた。第71サイクルの
診断で残っていた for 変数基底（197 グループ）を、本変更で対象に加えた。
新規レイアウトは増やさず、既存 MR レイアウトに折り込んだ。

## なぜプレヘッダではないか

for 変数にはテーブル構築子初期化子がなく、テーブルであることの証明が
ないため、プレヘッダ評価は 0 回ループで元のコードが読まない読取を評価し、
非テーブル基底ではエラーを生む。そこでキャッシュはループ毎の本体入口、
すなわちループ本体ブロック内に、グループの初回読取を含む文の直前に挿入
する。初回読取がその文の head 位置にあり（条件式・局所初期化子・呼出
引数など、分岐・繰返し・関数本体の内側でないこと）、かつその文の中で
初回読取より前に完了する呼出がない場合に限り適用する。これにより
キャッシュは初回読取とまったく同じ時点で評価され、初回読取のエラー挙動
（副作用の有無を含む）が保存される。後続の読取は本体ブロックの局所変数に
支配される。基底の証明は従来と同型に保守的である：goto／label を含む
関数では対象外、基底への書込み回数 0、プログラム全体でのエスケープなし
（Index の対象以外の Name 出現はすべて失格。別名経由の書込み・
setmetatable 経路を閉じる）、ループバリア（未知呼出・メソッド呼出・
状態付き builtin）および同一 (基底, キー) への書込みによるグループ失格は
従来通り。

  実行速度の改善と引換えに許容範囲内と判断した。

## 残課題

- 初回読取が分岐内・ネストしたループ本体内・repeat 文内・文内の先行呼出の
  後にあるグループは、現行の本体入口キャッシュでは扱えない（v1 の制限）。
- 未知呼出バリアの緩和（被呼出関数の非書込み証明）は長期項目。
- 直線メンバ読取 CSE（第69サイクル候補 B）は本変更の後に位置付ける。
