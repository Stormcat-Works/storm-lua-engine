# 検証記録: メソッド定義の暗黙 self を S1／MR／SMC の予算会計に数える（Codex 第2回指摘7系・self 形）

- 実施: w4 第95サイクル（2026-10-31〜11-01、w6 第52サイクル完結監査の割当）
- 対象コミット: `335d1cf`（統合時に rebase で再採番）
- 対象ファイル:
  `crates/storm-lua-minify/src/passes/single_member_cache.rs` /
  `loop_member_reads.rs` / `straightline_member_reads.rs`

## 問題

第218ラウンドで LICM／キャリア合成（AE）はメソッド定義の暗黙
`self` を予算会計に数えたが、同じ会計を使う S1（単一メンバ
キャッシュ）／MR（ループメンバ読み）／SMC（直行メンバ読み）の
3 パスは、関数本体へ入る際に明示パラメータ数だけを文脈へ積んで
いた。メソッドでは実際の同時有効ローカルが会計より 1 多いため、
ゲート視点 199／真値 200 の境界形状でキャッシュローカルが
201 本目になり、対象モードでのみ読込不能コードが生成された
（w6 第52サイクル監査 a1／a7／a10。第218ラウンドのコミット
メッセージ自体がこの共有欠陥を所有者向けに記録していた）。

## 修正

第218ラウンドと同型の迎撃を 3 パスそれぞれの `transform_statement`
の Funcstat アームへ追加する: ターゲットがメソッド名の場合、
関数本体へ入る際にパラメータ数＋1 の予算文脈を積む。関数ノード
自体は定義形を見られないため迎撃位置は Funcstat 側になること、
Localfunc はメソッドになり得ないこと、`t.m = function(self, ...)`
の代入形は暗黙 self ではないことから、対象はこの 1 形に限られる。

## 検証

- 単体テスト 6 件（各パス、抑止／発火の境界対）: メソッド形で
  明示パラメータを従来の発火境界から 1 本減らした数にし、self
  込みでちょうど 200 になる形状が抑止され、1 本下では発火する
  ことを確認。**修正前コードでは抑止側 3 件が全て失敗する**
  ことを別途確認済み（テストの非空転性）。
- パイプライン検証（w6 監査ケース、diffexec 全構成）: ベース
  （第225ラウンド先端）では a1（S1）／a7・k1（MR）／a10（SMC）
  が既定構成で、a5／l3 が function-local-globalization 無効化
  時に、それぞれ対象モードのみ乖離。ヘッドでは全 8 実行が
  全構成一致。
- a5／l3 の帰属について: w6 第53サイクルは api-alias 帰属と
  したが、本サイクルの切り分けで api-alias 無効化では不変で
  あり、本修正で回復したため、本クラス（共通段のメンバ
  キャッシュ挿入が勝者レイアウト joint-api-local-licm 内で
  発火）が真因と確定した。LICM 自身のゲートは第218ラウンド
  の回帰テスト（a5 と同一形状）で発火しない。
