# 出力シーケンスループ合成にローカル予算チェックが無く、200 上限の関数が読込不能コードを生成した（2026-10-31、未公開）

## バグ

w6 第52サイクル（Codex 指摘 #7 系「ローカル挿入パスに予算チェックなし」クラスの完結監査）で発見。出力シーケンスループ合成（`output-sequence-loop-synthesis`）は、6 件以上の連続した `output.setNumber`／`output.setBool` 呼び出しを「値テーブル＋数値 for ループ」に置き換える際、囲み関数の同時有効ローカル上限を一切確認せず、列のブロックへ数値 for（ループ変数＋隠れ制御値 3 ＝ 4 ローカル）を挿入していた。引数 197 の関数に 8 連続の出力呼び出しがあると、挿入で同時有効ローカルが 201 になり、生成コードが VM に読込を拒否された。再現（c52-probes/c13-outloop-197）: plain は正常、opt／safe／target32／target128 が全て vm-error。引数 196 の対照（c14）は合成が発火して全構成一致した。for の制御値はグローバル化できないため、後段のグローバル化パスによる救済も効かない。

## 原因箇所

`crates/storm-lua-minify/src/passes/output_loops.rs`。第208・212・213ラウンドで他の挿入パス（S1／MR／SMC／LICM／純粋呼出キャリア合成）へ入った `max_active_locals` + `MAX_LOCALS` の予算チェックが、このパスには入っていなかった。同クラスの 6 例目（監査で静的列挙した未会計の挿入パスの一つ）。

## 修正

- チャンク内の全ブロックについて「囲み関数の保守的最大値」を事前計算するマップを追加した（チャンク自体は引数 0 の最外関数、メソッド定義は暗黙の `self` を加算。共有ヘルパー `max_active_locals` を関数ごとにメモ化）。
- 列の合成直前に、そのブロックの囲み関数の最大値＋4（for の制御ローカル）が `MAX_LOCALS`（200）を超える場合は合成をスキップし、元の呼び出し列をそのまま残す。
- 回帰テスト 2 件を追加: 引数 197 でスキップ／引数 196 で発火。

## 検証

- ワークスペーステスト全通過（1,551 件 = 第213ラウンド時点 1,530 + 新規 21、本ラウンド分は output_loops の 2 件）。
- 再現 c13-outloop-197 は全 5 構成で正常終了・トレース一致に転じ、c14 の対照では合成が維持された（base／head の diffexec は同ケースで機能的に同定済み）。
- Tier FULL（base `6161dbf03` = FULL-VERIFY-TIP → head、実世界コーパス 4,155 件 × 4 条件 = 16,620 行、開発ホスト1）: base／head の corpuscheck TSV がバイト単位で完全一致（SHA-256 `f4d49f79…`、両側とも success 4,128／error 27 × 4 条件）。上限近傍での発火抑制のみのため、コーパスへの影響ゼロは設計どおり。回帰 0 件。
