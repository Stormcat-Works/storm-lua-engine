## 修正（統合ブランチの通常コミット）

- `d0e2865`（wasm32 実バグ）: FxHash 系の内部ハッシュの状態を固定幅 `u64` に統一した。種定数が 32bit `usize` に収まらず wasm32 でコンパイル不能だった問題で、同系の実装が3箇所（構文クレートの由来解決、minify の2パス）にあり全て揃えた。64bit 環境でのハッシュ値の列が従来と完全一致する形にしてあり、interning の順序に由来する出力変化は生じない（Tier FULL のバイト同一で裏付け）。
- `6118faf`（CI ゲート整合）: `cargo fmt --all` の従来分10箇所を適用。アーキテクチャ規則に `storm-lua-build` → `storm-lua-vm` と `storm-lua-minify` → `storm-lua-vm` の依存許可を追加（いずれも load 合法性ゲートの正当な設計）。clippy は CI 条件（全ターゲット・全特徴・`-D warnings`）で再現した警告を個別に解消し、rustdoc の壊れた内部リンク1件も直した。いずれも意味変更なし（未使用コードの除去、テスト側のスコープ付き許可、借用の簡約、範囲判定の等価な書き換え等）。

  - native（ubuntu）: 全ステップ成功。
  - native（macOS）: 全ステップ成功。
  - native（Windows）: `cargo check` で失敗。`sha2-asm` 0.6.4 のビルドが、MSVC の `cl` がアセンブリ源ファイル（`.S`）を無視してオブジェクトを生成せず、リンク時に LNK1181 となる。sha2 の asm 機能は統合ブランチでのみ有効化されたもの（公開 main は無効）で、Windows CI 未経験だったために潜在していた。出力に影響しない加速機能であり、処置案は asm 機能を落とすこと（Source Map の完全性ハッシュの速度のみに影響）。
