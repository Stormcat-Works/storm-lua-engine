# 生成由来の解決のイベントソート分割（2026-10-27、未公開）

compile の固定費のうち、生成由来の解決（`GeneratedOrigins::from_arena`）
のイベント処理のソートコストを減らした。生成 Lua・候補選択・schema1 の
マップ本体は維持する。Map 比 1.2 の目標は未達のままであり、この変更は
その達成を主張しない。

## 原因

解決の骨格（イベント構築＋ソート＋active 維持）は合成入力で約 0.84ms
あり、そのうち単一ソートが約 0.50ms を占めていた。イベントは
emission 1 件あたり開始・終了の 2 件（計 21,450 件）で、タプル
（offset、開始フラグ、emission index）の順序でソートされていた。

## 変更

- `crates/storm-lua-syntax/src/provenance.rs` のみ変更し、公開 API の
  シグネチャは変えていない。
- 開始イベント列と終了イベント列を別々にソートし、イベントループで
  2 本の整列済み列をマージして処理する。タプル順序は emission index
  の一意性により全順序のため、2 列のマージ順は全イベントの単一ソート順
  と exactly 一致する。emission の終了順への依存はしていない。
- ループ本体（gap の選択・append、active の維持、constructs、
  dispositions）は変えていない。

## 効果

- 合成入力（dense-normal、31 反復中央値）で、解決を含む測定が
  約 4.84ms から約 4.42〜4.53ms へ減った。解決結果の件数は変更前後で
  同一（mappings 9,284・origins 10,725・contexts 0・constructs 6,883）。
- 骨格だけのマイクロベンチでは約 0.84ms から約 0.56ms へ減った。
- 全パス無効の compile の Map 差は約 6.65ms から約 6.2〜6.5ms へ
  減った（実行変動を含むため幅を持ってみる）。

## 検証

- 対象 3 クレートとワークスペース全件のテストが成功した。
  `cargo xtask check`・fmt・clippy（警告 0）を通過した。
- 実コーパス全件比較では、成功／失敗・生成コード・Map 中核・
  正規化済み Map 全体のすべてが差分 0 件だった（詳細は作業記録参照）。
