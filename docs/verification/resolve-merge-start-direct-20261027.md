# 生成由来の解決における開始イベント列の直接マージ（2026-10-27、未公開）

compile の固定費のうち、生成由来の解決（`GeneratedOrigins::from_arena`）
のイベントマージで、開始イベントのタプル列の具体化をやめた。生成 Lua・
候補選択・schema1 のマップ本体は維持する。Map 比 1.2 の目標は未達の
ままであり、この変更はその達成を主張しない。

## 原因

従来は radix ソート済みの開始順序から、開始イベントのタプル列
（offset・種別・emission index）を別 Vec へ具体化してから終了イベント列と
マージしていた。タプル列は emission 件数分の確保と push を要し、マージ
自体に必要な情報は emission index だけで足りる。

## 変更

- `crates/storm-lua-syntax/src/provenance.rs` のみ変更し、公開 API の
  シグネチャは変えていない。
- 開始タプル列の具体化をやめ、マージループが radix 済みの開始順序を直接
  走査する。開始イベントの offset は emission からその場で読み、終了
  イベントとの同 offset では終了を先に取る（従来のタプル比較と同一の
  順序規則を、開始 offset < 終了 offset の厳密比較で表す）。
- 開始イベント間の順序は radix ソート結果そのままで、終了イベント列の
  構築・ソート・マージ本体の処理は従来どおりである。したがってイベント
  列の順序は従来と完全同一で、解決結果は変わらない。

## 効果

- 合成入力 4 件の決定的な計数で、解決結果の件数は変更前後で完全同一
  （dense-normal：mappings 9,283・origins 10,723・constructs 6,881・
  dispositions 0、他 3 入力も同一）。
- 時間測定は計測専用マシンで旧・新バイナリの交互測定（31 反復中央値、
  順序回転・各入力 4 ペア、低負荷）を行った。print＋from＋resolve の
  中央値は dense-normal で約 7.6ms から約 7.4ms（新 4 勝、約 -3.5%）、
  draw で約 1.14ms から約 0.93ms（新 4 勝、約 -18%）だった。
  dense-lexical は 2 勝 2 敗で互角、scale-80 は新 1 勝 3 敗で約 +0.04ms
  の小幅悪化だった。全体としては悪化方向の証拠はなく、開始列の
  具体化除去による小幅な改善とみる。絶対値は計測マシン固有のもので、
  過去の他マシン系列とは比較しない。
- 実コーパス全件比較では差分 0 件だった（下記）。

## 実コーパス検証

- 対象は実コーパス 4,155 件で、4 条件（default・std × map on/off）・
  16,620 行を base と head で比較した。欠落 0 行で、両 TSV はバイト同一
  だった。成功／失敗・生成コード・Map 中核・正規化済み Map 全体の
  すべてに差分はなかった。コーパスの内容は記録しない。
