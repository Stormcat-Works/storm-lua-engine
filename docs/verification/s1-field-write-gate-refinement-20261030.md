# S1 のフィールド書込み失格条件の精密化（2026-10-30）

## 変更

単一メンバキャッシュ（S1）のループ失格判定を精密化した。従来は
ループ内のフィールド書込み（`base.key = ...` 形式の代入と
メソッド定義）が理由を問わずループ全体を失格させていたため、
組込みテーブルと無関係なプレーンなテーブルへの書込みがある
だけで、キャッシュ可能なメンバ呼出を含むループが発火しなかった。
本変更では、書込みの基底が次の3段で無害と証明できる場合に限り
失格させない。

1. 基底が組込みを指す（root そのもの、またはメンバ）場合は
   従来どおり失格。
2. 基底が組込み root のエイリアスと証明できる
   （既存の `alias_table_root` 証明）場合は従来どおり失格。
3. それ以外は、基底がコンストラクタで作られたプレーンな
   テーブルでエスケープしないことが証明できる
   （ループメンバ読取の `base_proven` を再利用）場合に限り無害
   とする。エスケープ解析が `setmetatable` による
   `__newindex` 経路とエイリアス経由の書込みを閉じる。
   基底が素の Name でない形状（入れ子 Index・呼出結果・括弧）は
   証明対象に含めず従来どおり失格させる。

判定はループ失格走査1回の中で BindingId 単位にメモ化する
（根拠走査がチャンク全体に及ぶため）。

## 単体テスト

モジュールテスト 34 件成功。主な内訳は次のとおり。

- 発火するようになった形状：プレーンなローカルテーブルへの
  書込み、チャンク先頭で定義したグローバルテーブルへの書込み、
  ループ本体内の宣言、プレーンなテーブルへのメソッド定義。
  従来テスト `skips_loop_with_table_write` は本変更の対象形状
  そのものだったため、発火を表明するテストに書き換えた。
- 失格を維持する形状：root への書込み、root のエイリアスへの
  書込み、エスケープするテーブル、再代入されるローカル、
  コンストラクタでない初期化、入れ子の基底、無害な書込みと
  root への書込みの混在。
