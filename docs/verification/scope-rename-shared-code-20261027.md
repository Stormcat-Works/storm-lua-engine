# scope-renaming の変換コード共有による追跡コスト削減（2026-10-27、未公開）

scope-renaming（`scope_rename`）は、改名するノードごとに由来の
derivation を記録する。その際、変換コード文字列
`scope-renaming` の `Arc<str>` を由来本体と名前由来の項目ごとに
毎回新規確保していた。呼出側が所有する1個のコード文字列を
改名全体で共有する方式に変更し、記録内容を変えずに追跡コストを
削減した。生成 Lua・候補選択・schema1 のマップ本体は維持する。
Map 比 1.2 の目標は未達のままであり、この変更はその達成を主張しない。

## 原因

追跡差の内訳切り分け（合成入力 dense-normal、計数アロケータ付き
ハーネス、11 反復中央値）では、scope-renaming 単独の追跡差
7,587 回（無追跡 5,497 回→追跡 13,084 回）のうち、改名ノード
961 件に対する内訳は次のとおりだった。

- 基礎（capture・クローンの COW 等）：約 860 回。
- スロット置換（import＋`Arc::new`）：961 回（1 回／ノード）。
- derive 理由：5,766 回（約 6 回／ノード）。
  - 本体由来：1,922 回（変換コード `Arc<str>` 1 回＋理由テール
    1 回／ノード）。
  - 名前由来：3,844 回（名前ベクタの複写＋変換コード＋理由テール等）。

変換コードの確保は、由来本体と名前由来の項目でそれぞれ発生して
いた。コード文字列の内容は全ノードで同一であり、由来の比較・格納は
文字列内容で行われるため、共有しても記録内容は変わらない。

## 変更

- `crates/storm-lua-syntax/src/deferred_origin.rs` に
  `StoredOrigin::derive_in_place_code` と `derive_action_code` を追加した。
  呼出側所有のコード文字列を再利用し、従来の `derive_in_place`／
  `derive_action` と同じ手順（kind の Derived 化、変換コードの内容比較に
  よる格納、理由の追加・変換）を行う。公開 API の追加のみで、既存
  シグネチャは変えていない。
- `crates/storm-lua-syntax/src/node_arena.rs` に
  `NodeArena::finish_rename_with_code` を追加した。`finish_rename` と
  同じ手順で、由来本体と名前由来の全項目に同一のコード文字列を使う。
  `finish_rename` 自体は、ノードごとに1個のコード文字列を作って委譲
  する形に変更したため、他の呼出側（closed_fields 等）でもノード内の
  共有恩恵を受ける。記録内容は従来と同一である。
- `crates/storm-lua-minify/src/passes/scope_rename.rs` の
  `apply_renames` は、改名全体で1個のコード文字列を作り、2箇所の
  finish 呼出を `finish_rename_with_code` に変更した。

候補選択・改名対象・生成コードには手を入れていない。理由テールや
名前ベクタの扱いは従来どおりで、共有したのは変換コード文字列の
確保だけである。

## 測定

合成入力は dense-normal（46,022 バイト）。VM 2 コア、計数アロケータ
付きハーネスで各条件 11 反復の中央値を測った。

| 測定 | 変更前 | 変更後 |
| --- | ---: | ---: |
| scope-renaming・追跡なし確保回数 | 5,497 回 | 5,498 回（誤差範囲） |
| scope-renaming・追跡あり確保回数 | 13,084 回 | 11,163 回 |
| scope-renaming・追跡差（確保回数） | 7,587 回 | 5,665 回（約 −25%） |
| scope-renaming・追跡あり確保バイト数 | 1,712,317 B | 1,650,845 B |
| api-alias・追跡なし確保回数 | 115,530 回 | 115,531 回（誤差範囲） |
| api-alias・追跡あり確保回数 | 131,179 回 | 128,614 回 |
| api-alias・追跡差（確保回数） | 15,649 回 | 13,083 回（約 −16%） |
| api-alias・saved／コード長／ノード数 | 7127／13841／6883→5940 | 同一 |

時間差は負荷変動が大きく、時間改善は主張しない。

## 検証

- 回帰テスト `node_arena::cow_tests::finish_rename_with_code_matches_finish_rename`
  を追加した。同一ノードの改名を新旧両経路で実行し、由来・名前由来・
  シリアライズ済み AST・生成コードの一致を検証する。
- 対象 3 クレート（syntax 103・minify 441・build 126）とワークスペース
  全件（50 スイート）が成功。`cargo xtask check`・fmt・clippy（警告 0）
  を通過。
- 実コーパス全件（4,155 ファイル×4 条件）の比較では、成功／失敗
  （4,127／28）・生成コード・Map 中核・正規化済み Map 全体のすべてが
  差分 0 件で、両 TSV はバイト同一だった。検証バイナリの SHA-256
  相違も確認（base 7197699c…、head 53453edc…）。
