# 画面ループ合成（ordered／periodic）にローカル予算チェックが無く、200 上限の関数・チャンクが読込不能コードを生成した（2026-10-31、未公開）

## バグ

w6 第52サイクル（Codex 指摘 #7 系「ローカル挿入パスに予算チェックなし」クラスの完結監査）で発見。画面ループ合成（`ordered-screen-loop-synthesis`／`periodic-screen-loop-synthesis`）は、繰り返し現れる描画呼び出し列を「値テーブル＋数値 for ループ」に置き換える際、囲み関数の同時有効ローカル上限を確認せず、列のブロックへ数値 for（ループ変数＋隠れ制御値 3 ＝ 4 ローカル）を挿入していた。引数 197 の関数に 8 連続の描画呼び出しがあると、挿入で同時有効ローカルが 201 になり、生成コードが VM に読込を拒否された。再現（c52-probes/c17-screen-197）: plain は正常、opt／safe／target32／target128 が全て vm-error。チャンク形（c18-screen-chunk）も、後段のグローバル化パスを無効化した構成では同じく vm-error になった。for の制御値はグローバル化できないため、既定構成でも関数形は救済されなかった。

## 原因箇所

`crates/storm-lua-minify/src/passes/screen_loops.rs`。第208・212・213・214ラウンドで他の挿入パスへ入った `max_active_locals` + `MAX_LOCALS` の予算チェックが、このパスには入っていなかった。同クラスの 7 例目。

## 修正

- チャンク内の全ブロックについて「囲み関数の保守的最大値」を事前計算するマップを追加した（第214ラウンドの output_loops と同型。チャンク自体は引数 0 の最外関数、メソッド定義は暗黙の `self` を加算）。
- ordered／periodic 両変形の共通入口で、そのブロックの囲み関数の最大値＋4（for の制御ローカル）が `MAX_LOCALS`（200）を超える場合は合成をスキップし、元の呼び出し列をそのまま残す。
- 回帰テスト 2 件を追加: 引数 197 の関数でスキップ／チャンク＋引数 196 の関数で発火。

## 検証

- ワークスペーステスト全通過（1,553 件、本ラウンド分は screen_loops の 2 件）。
- 再現 c17-screen-197 は全 5 構成で正常終了・トレース一致に転じ、c18-screen-chunk はグローバル化系を無効化した構成でも正常になった。
- Tier FULL（base `2d8021aca` = FULL-VERIFY-TIP → head、実世界コーパス 4,155 件 × 4 条件 = 16,620 行、開発ホスト1）: base／head の corpuscheck TSV がバイト単位で完全一致（SHA-256 `f4d49f79…`、両側とも success 4,128／error 27 × 4 条件）。上限近傍での発火抑制のみのため、コーパスへの影響ゼロは設計どおり。回帰 0 件。
- 付記: c17b（引数 196 の対照）に ordered 合成を無効化した構成で残る opt の vm-error は、periodic 合成の for と api ローカル化（Codex 指摘 #7 の既知残件、w4 割当）の挿入の合成が原因であり、本ラウンドの対象外として記録した。
