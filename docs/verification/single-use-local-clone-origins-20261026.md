# 単一使用ローカルのクローン由来共有による追跡コスト削減（2026-10-26、未公開）

単一使用ローカルのシンク（`single-use-local-sinking`）で、初期化式を
複製する `clone_expanded` の由来付けを共有するよう変更した。生成 Lua・
候補選択・schema1 のマップ本体は維持する。Map 比 1.2 の目標は未達の
ままであり、この変更はその達成を主張しない。

## 原因

`NodeArena::derive_from` の高速経路は、対象ノードの値全体が源ノードと
等しい場合にのみ由来スロットを共有する。`clone_expanded` は置換対象の
名前を初期化式の複製で置き換えながら木を複製するため、最初の置換以降は
後続ノードの子 ID がずれ、値の等価性がほぼすべてのノードで崩れる。
結果として、変更のないクローンにもかかわらず低速の書き換え経路（理由の
生成・トークン／名前の保持判定・新規スロット確保）が走っていた。これは
API 別名パスで `derive_from_clone` が解消したのと同じ構造である。

## 変更

- `crates/storm-lua-minify/src/passes/locals.rs` の `clone_expanded` のみ
  変更し、`derive_from` を `derive_from_clone` に置き換えた。置換された
  名前そのものは従来どおり `relate_from_role` で使用箇所との関係を記録
  する。`derive_from_clone` は種類が異なる場合や source snapshot を
  共有しない場合に従来の `derive_from` へ委譲するため、本物の置換は
  従来どおり書き換え理由を記録する。スロット共有後に
  `relate_from_role` が走る場合も、関係の記録はスロットをコピーしてから
  行うため、源のスロットが壊れることはない。
- この変更の適用範囲は単一使用ローカルのシンクだけである。同じヘルパー
  を使う他のパスはなく、他のパスのクローン箇所は今回変更していない。

## 測定

合成入力（500 組の `local s = left + right * 3 + up * 5` と直後の
`result = s * 2` からなる 1,500 行。シンクの条件は「直後の文が呼出を
含まない代入」であるため、出力呼出を直接のシンク先にはできない）。
VM 2 コア。計数アロケータ付きハーネスで各条件 31 反復の中央値を測った。

| 測定 | 変更前 | 変更後 |
| --- | ---: | ---: |
| パス単体・追跡なし確保回数 | 38,863 回 | 38,863 回（不変） |
| パス単体・追跡あり確保回数 | 67,868 回 | 48,368 回 |
| パス単体・追跡あり確保バイト数 | 12,972,374 B | 12,042,374 B |
| パス単体・追跡差（確保回数） | 29,005 回 | 9,505 回 |
| パス単体・追跡差（確保バイト数） | 1,814,256 B | 884,256 B |

追跡なし側が変更前後で完全に同一であることから、削減が追跡経路だけの
ものであることを確認した。時間については、同じハーネスの追跡差が
約 3.17ms から約 1.72ms へ縮んだ一方で、単独パス測定の反復では変動が
大きく、時間改善としては主張しない。確保回数の削減が確実な効果である。

## 同一性

公開コンパイル全体で上記合成入力を前後比較した（stash による前後比較）。

- 生成コードは SHA-256 一致（20,977 バイト）。勝者は変更前後とも
  `optimized:locals/joint-api`。
- マップの mappings・names・sources・sourcesContent・version は同一。
  `x_storm` の compilation・constructs・generated・mappings・relations・
  schemaVersion・sources も同一。
- 変わったのは `x_storm` の理由・由来・処分だけである。理由一覧は
  13 件から 11 件へ減り、消えたのは `single-use-local-expression-copy`
  の書き換え理由 2 件（binary:+ と binary:*）だけである。由来 14,004 件
  のうち 1,500 件は、唯一の理由がその複製理由だったもので、由来種別が
  derived から source へ変わり、同じ primary span を直接指すように
  なった（初期化式 1 個あたり二項演算子 3 件 × 500 シンクと一致する）。
  残りの由来は、理由の削除に伴う番号付け替えを除いて同一である。
  処分 1,228 件はすべて、元の span は同一で理由番号だけが付け替わった
  ものである。インラインされた複製の根に付く `single-use-local-read`
  の使用箇所関係は維持されている。
- `producer` の差は、測定時の未コミット状態を示す dirty フラグだけで
  あり、リビジョンは同一である。`integrity` の差は内容の差を覆う
  ダイジェストによるものである。
