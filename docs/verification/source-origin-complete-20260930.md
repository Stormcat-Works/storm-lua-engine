## 主な修正

### 関数の配置変更と残った構文

callbackごとに排他的な関数を同じスロットへ配置する処理が、新しいASTを作る際に、周囲の無関係なノードまで由来を失っていた。コピー元を明示して、各元関数・宣言・参照の位置を保持した。同じ生成スロットを使っても、元の関数名を混同しない。

elseの既定代入を前へ移す処理、共通の値を再利用する処理、採用されなかった定数呼び出し候補の復元、数値スケール変更にも由来を接続した。元の場所に残る括弧や演算子をUnknownにしない。明示的に生成されたlocal helperをglobalizeするときも、名前の生成由来を保持する。ただし元の宣言の情報が欠けている場合は回復したことにしない。

### 数値の再表現

近似値、共有する数値リテラル、厳密な分数表現、逆数、符号を正規化した項、ビット判定を剰余式へ変える際の定数に、実際に使った元の値・演算の範囲を付けた。共通の数値定義は各元リテラルを関連範囲として保持する。

例えば`value*0.5`を`value/2`へ変える際の`2`は、無関係な原文の`2`ではなく、元の`0.5`から導いた値である。分数の約分では分子・分母、スケール変更では初期値と係数を区別する。必要な元データが欠けた場合、新しい定数をSyntheticへ逃がして0%にすることはしない。

### 描画ループと圧縮データ

引数列から作る等差・周期・テーブル参照式を、その列の元の引数へ対応させた。ループの制御・添字・保存領域は明示的な生成コードとする。等差列が添字一つに簡約される場合も、その読み出しは元の列を表すため、元の値が不明ならUnknownを残す。

共有の描画辞書では、パレットの値、符号化したpayload、復元される引数、まとめた呼び出しを分けて記録する。デコーダーの制御構造はSynthetic、実データは入力由来とする。元の呼び出しをラッパー経由で正規化した場合も、ラッパー内の固定引数と実引数の出所を保つ。

繰り返し描画列のhelperは、元の描画命令をそのまま持ち、各呼び出し位置と対応する繰り返し箇所を関連付ける。変換された圧縮データは多数の元引数を寄与元として持つので、文字ごとの可逆的な位置対応とは説明しない。

## 0%の品質と意味

汎用のNodeArena/mapperで未知の子を親の元位置で補う規則は追加していない。低レベルの不正確なmutationをUnknownへ失効させる規則は維持した。元の乗数、共有リテラル、ループの元の値、圧縮payloadの元データ、元の名前が欠けた負例を試験し、不明のまま残ることを確認した。

同じ値・スロット・関数を共有しても、元の出現を適当な文字列検索で推測していない。出力を生成する処理で、元ノードと生成範囲を明示的に記録する。一時的な原因調査の出力は製品コードから除去した。

| 分類 | 生成バイト数 |
| --- | ---: |
| Unknown | 0 |
| Source | 233,460 |
| Derived | 245,884 |
| Synthetic | 12,416 |

合計491,760バイト。元ソースのGroup精度に帰属した8,430バイトはすべて空白・改行・セミコロンで、非区切り文字は0だった。64設定ではSyntheticバイトもゼロである。Group/Nameは精度の別集計なので上表のkind別集計へ重複加算しない。

**0%は「由来不明がない」。** Source/Derivedは名前・式・文単位の対応を含み、複数の寄与元を持つ場合もある。Syntheticは生成理由が分かるだけで元ソースの一点を持たない。消えた変数や元の実行順の復元、最適化後の完全なステップデバッグを保証する指標ではない。
