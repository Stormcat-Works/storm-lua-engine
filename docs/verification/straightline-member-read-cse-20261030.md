# 直線メンバ読取 CSE（SMC レイアウト）の検証（2026-10-30、未公開）

## 変更

- `crates/storm-lua-minify/src/passes/straightline_member_reads.rs` を新規作成。
  直線コード上の反復メンバ読取（値位置の `B.K`、基底は素の Name・キーは
  リテラル）を、同一セグメント内で 1 回のキャッシュ局所化
  （`local c = B.K`＋各出現箇所の `c` 置換）にまとめる。
- セグメントは 1 ブロック内の `local`／代入文の最大ラン＋末尾の呼出なし
  `return`。呼出・制御フロー・Index／メソッド書込みを含む文はセグメントを
  区切る。グループはセグメント内のみで形成し、ブロック境界・関数境界を
  越えない。
- 基底の証明は `loop_member_reads` の証明をそのまま再利用（可視性を
  `pub(crate)` 化したのみで証明内容は不変）：書込み 0 の単一代入 local
  （テーブル構築子初期化子）または書込み 1 回のグローバル
  （チャンク頂点形または同一ブロック先行定義形）、goto/label なしの囲む関数、
  プログラム全体での非エスケープ。セグメント内では呼出・Index 書込み・
  基底書込みが起きないため、この証明だけでフィールド値の不変が従う。
  キャッシュ定義はプレーンなテーブルに対するリテラルキー読取のため全域・
  無副作用で、初回読取文の直前への移動は観測可能な挙動を変えない。
- `search.rs` に target モード限定レイアウト `joint-api-local-smc`／
  `joint-api-local-licm-smc` を追加（既存の local／licm レイアウトの上に
  SMC 変換を重ね、発火時のみ候補に加える。S1／MR とは合成せず別レイアウト
  とする点も同型）。速度順位は MR の下・基底レイアウトの上に置く
  （MR の節約は反復回数に比例し、SMC はブロック実行あたり固定のため）。
  描画後 polish の root-local-globalization 適用除外にも両レイアウトを追加した。
  速度順位の繰下げに伴い、キャッチオール `_` の順位も最下位へ繰り下げた
  （繰下げ漏れでは `none` レイアウトが joint-api-local と同順になり
  既存テスト 1 件が失敗することを確認し、修正済み）。
- 目標なしコンパイルには一切触れない（レイアウト生成は target 専用分岐内）。
