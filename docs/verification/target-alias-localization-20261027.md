# target 付きコンパイルでの api-alias local 化（2026-10-27、未公開）

## 背景と判断
ユーザー判断（2026-10-27）により、目標文字数付きコンパイルでは
文字数上限内で生成 Lua の実行速度を最優先する。従来は目標達成で
早期停止するだけだったが、本変更は目標内で速度最適化を実施する。
目標なしの最高圧縮とは混ぜない。

## 変更内容（`storm-lua-minify` のみ）
- `passes/api_aliases.rs` に `optimize_api_aliases_localized` を追加。
  別名定義をグローバル割当てではなくチャンク local 宣言で出す。
  選択は local コストでやり直すため、選択集合は縮小し得る。
  目標なしコンパイルは従来の `optimize_api_aliases` のみを使い、
  生成コードは変わらない。
- `search.rs` に target 限定レイアウト `joint-api-local` を追加。
  target 付きの場合のみ候補として生成し、目標なしでは生成しない。
- 勝者選択（target 付きのみ）：目標内に収まる候補の中では
  `joint-api-local` > `joint-api` > その他の順で選び、同順内は
  文字数・順序で決める。目標を超える速度版が、目標内に収まる
  候補に勝つことはない。目標に収まる候補がない場合は従来通り
  最小文字数で選ぶ。
- 描画後 polish の root-local-globalization は、local レイアウトに
  対しては適用しない（速度版が global に戻されるのを防ぐ）。
- 既存の target 関連テスト 4 件は、候補集合の拡大（レイアウト追加に
  よる attempted・candidate_sizes の増加）に合わせて更新した。
  変更前は target 未達時の候補集合同一性を主張していたが、local
  レイアウト分だけ集合が広がるのが新しい契約である。

## 適用範囲と既知の限定
- 速度版が選ばれるのは、候補チェックポイント（バッチ評価後）または
  フルサーチフォールバックで目標を満たす場合である。
  原文・ベース段階のチェックポイントで既に目標を満たす場合は、
  従来の OBJ-2 契約通り最適化なしで返る（速度版は生成されない）。
- 一般 LICM（ループ不変な純粋 host 読取のホイスト）は本変更の
  範囲外で、次サイクル以降の課題として残る。
- ホスト検証用の `compile_code_with_verifier` 経路は本変更の対象外で、
  target 付きでも従来通り最小文字数で選ぶ。通常の `compile_code`
  経路（satisficing＋フルサーチフォールバック）のみが速度優先である。

## 代表入力での測定（開発ホスト2）
- 制御例：目標なし 138 文字 → target 146 で local 版 145 文字
  （`local c=input.getNumber`、output 別名は local コストで不採用）。
  命令数 39 → 39（素呼出は local 化で命令数不変という既知モデル通り）。
  壁時間（交互・31 反復、MEASURE.lock 取得、loadavg 約 1.5）：
  ペア中央値 −1.3%（24/31 対で改善）。
- 描画例：目標なし 145 文字 → target 160 で local 版 156 文字
  （`local a=screen`、メンバ呼出は `a.setColor`・`a.drawRectF`）。
  命令数 2447 → 2318（−129、約 −5.3%）。
  壁時間（同条件）：ペア中央値 −3.3%（30/31 対で改善）。
- 実行結果同一性：両例とも vmbench 単発で出力スナップショット・
  描画コマンド数が目標なし版と一致（制御：numbers 2.5/0・booleans
  true、描画：コマンド 258 件）。

## コーパス全体の target モード差分（読み取り専用、内容の記録なし）
- 条件：各ファイルの目標なし勝者サイズ＋32 文字を目標とした。
- 対象 4,155 件中、目標なし・target とも成功 4,127 件／失敗 28 件で一致。
- target 版の勝者レイアウト：`joint-api-local` 2,883 件、
  `none` 745 件、`source` 338 件、`joint-api` 156 件、
  `tokens` 5 件。
- 文字数差の合計は＋42,666 文字（最大＋32、最小−16、変化あり
  3,525 件）。うち local 版の寄与は 2,883 件で＋27,001 文字
  （local 版のうち 380 件は目標なし版と同サイズ）。
  残りの差分は、目標内に収まった原文・直接候補がバッチ評価前に
  返される従来の satisficing 早期復帰によるもので、local 化とは
  別の要因である。target を超えたファイルは 0 件。
- 実行速度のコーパス全体への外挿は行わない。コーパスファイルは
  単体実行できないため、速度効果は上記の代表入力でのみ主張する。

## コーパス検証（目標なし・base 対 head）
- base：統合先端 `8523bcc2`（第25ラウンド）、head：本変更適用後の
  `muse/w4`。条件は4系統（default／std × Mapなし／あり）。
- 結果：全条件・全4,155件で完全一致（identical）。成功／失敗は
  両側とも成功 4,127／失敗 28、生成コードの長さ・SHA-256、Map 中核、
  正規化済み Map 全体まで差分 0 件。目標なしコンパイルは
  バイト同一であり、本変更は目標付きコンパイルにのみ影響する。
- 検証 TSV はワーカー記録に保存（`workers/w4/corpus-verify-c8/`）。
  コーパスの内容は記録していない。
