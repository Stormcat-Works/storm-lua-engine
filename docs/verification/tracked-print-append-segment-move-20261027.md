# tracked 印字の Fragment append におけるセグメント Vec の移動化（2026-10-27、未公開）

## 変更
- `crates/storm-lua-syntax/src/print.rs` の `Fragment::append` のみ変更
  （公開 API・Fragment のサイズ不変）。
- 自セグメントが空の場合、相手の segments Vec を新規確保＋全件コピー
  せず丸ごと移動する。オフセットは現地で加算し、オフセットが 0 の
  場合は無加工で移動する。block の先頭パートや join／cat の最初の
  セグメント付きパートなど、従来は毎回 Vec 確保＋コピーをしていた
  箇所が対象。
- セグメントの順序・値・オフセットは従来と同一で、生成コードと
  emissions は変わらない。

## 測定
- 合成入力 dense-normal（開発ホスト2、31 反復中央値、時間測定は
  共有 MEASURE.lock を取って実施）。
- tracked 印字：旧・新バイナリの交互 3 ペアで、旧 1.198／1.193／
  1.185ms に対し新 1.099／1.092／1.080ms（一貫して約 −0.10ms、
  約 −8%）。emissions は 10,725 件で同一。
- plain 印字（追跡 AST 上）：両者とも約 0.35〜0.37ms で不変。
  無追跡側は segments が常に空のため影響がないことと整合する。

## 同一性
- dense-normal のダンプ比較：旧・新バイナリで code 全文＋全 10,725
  emission（node・site・token・start・end・reason code）の SHA-256
  が完全一致した。
- 実コーパス全件比較（4,155 ファイル×4 条件）：成功／失敗
  （4,127／28）・生成コード・Map 中核・正規化済み Map 全体まで
  差分 0 件で、両 TSV はバイト同一だった。
- 対象 3 クレートとワークスペース全件のテストが成功し、xtask check・
  fmt を通過した。syntax クレートの clippy は警告なし。
  ワークスペース全体の clippy で minify のテストコードに警告 2 件が
  出るが、統合先端由来で本変更のファイル外のため、本変更による
  新規警告ではない。

## 残課題
- tracked 印字の残り（約 1.09ms のうちセグメント機構分）は、サイズを
  増やさないセグメント Vec 確保削減か、arena 側の削減でないと
  改善が見込めない段階が続く。次は resolve の骨格残りの分解か、
  arena 側の内訳切り分けが候補。Map 比 1.2 の目標は未達のまま。
