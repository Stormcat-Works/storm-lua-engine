# constant-folding の積極的恒等式（x * 0 / x - x）による非有限値・実行時エラーの喪失（2026-10-30、未公開）

## バグ

constant-folding パス（積極モード）の恒等式 `x * 0 → 0`、`0 * x → 0`、
`x - x → 0` は、相手被演算子が副作用なし（movable）であることだけを
条件に発火していた。しかしこれらの恒等式は `x` が有限数である場合に
しか成り立たない。

- `local p = 1/0`（+inf）に対し `p * 0`、`0 * p`、`p - p` はいずれも
  NaN でなければならないが、最適化後は 0 になった。そのため
  `(p * 0) ~= (p * 0)` が plain の true に対して false になり、
  `(p * 0) == 0` が false のところ true になった。`p * 0 + 1` も
  NaN のところ 1 になった。
- `local s = "a"` に対する `s * 0` は実行時エラーでなければなら
  ないが、最適化後は 0 となり、エラーが消えて後続処理が実行された
  （plain は vm-error、最適化後は ok で発散）。
- 数値文字列（`"10" * 0`）の強制変換は 0 で一致するため、この形では
  発散しないが、名前経由では型・値域を静的には証明できない。
- safe モード（exact 経路）では発火しない。最小再現は chunk レベルの
  ローカルに inf を伝播させ、関数内で当該演算を行い自己比較する形。
  リテラル直書き `(1/0 * 0)` は BinOp 被演算子の可動性条件により
  発火しなかった。

単独パス無効化スイープ（正本 73 件）で constant-folding の無効化
でのみ直ることを確認した。

## 原因箇所

`crates/storm-lua-minify/src/passes/literal_folding.rs` の
`fold_node_inner` における積極的恒等式 3 件（ゼロ積 2 件・自己減算
1 件）。被演算子の有限性を確認していなかった。一般リテラル評価
（`eval_binary` + `literal_node`）は非有限な結果の具体化を拒否する
設計だったが、その下流の恒等式がその保護を迂回していた。

## 修正

3 件の恒等式すべてに、捨てる側の被演算子が有限の数値リテラルである
こと（`finite_number_literal`）を発火条件に追加した。名前や一般式は
有限性を証明できないため発火しなくなる（リテラル同士の場合は一般
評価が先に処理する）。検証を弱める変更はない。

回帰テスト 3 件を追加した（修正前は 2 件が失敗し、修正後に合格を
両方向で確認）:

- `zero_product_keeps_unproven_operand`（`x*0`、`0*x`、`1e999*0`）
- `self_subtraction_keeps_unproven_operand`（`x-x`）
- `zero_product_still_folds_finite_literals`（`3*0 → 0` は維持）
