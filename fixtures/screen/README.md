# 採用済みの画面契約

`cases-v1.json`は入力命令と画素の期待値、`manifest.json`は契約名・ケース数・ファイルSHA256です。外部のアプリや元データをcloneする必要はありません。このデータの形式と更新はstorm-lua-engineが所有します。

JSONでは各ケースを1行にまとめ、差分の単位をケースに揃えています。各ケースは`id`、`width`、`height`、`ops`、`expectedRgbaRle`で構成されます。RGBAのrunは`[count,r,g,b,a]`で、透明背景も含む画面全体を表します。`ops`はテスト用の入力記法であり、公開WASM ABIとは別です。過去に採用したline入力の一部にある`x3/y3`は線分では使わない値として保持します。

**期待値を現在の実装から再生成するコマンドは提供しません。** 不一致が起きたら、まず実装・規則・テスト入力を調べます。契約の変更が必要なら、独立した観察、数値の導出、変更対象をレビューし、ケース本体とmanifestを同じ変更で更新します。ハッシュを更新したこと自体は正しさの証明ではありません。

`python3 tools/check_screen_fixtures.py`（リポジトリルートから）はschema、有限座標、件数、ID、RGBA範囲、全画素の充足、ハッシュを検証します。Native、WASM、ブラウザのテストは直接描画と実Lua実行の結果を比較します。実装からテストデータを取得する逆依存はありません。

731ケースの入力・期待RGBAは、整理前に採用済みだった内容を変えずに保持しています。第三者由来部分の権利表示は[許諾原文](../../licenses/screen-components-MIT.txt)を参照してください。元ソースのvendor、観察報告や採取カード一式はこのコーパスに含めません。
